# Re-derive a pre-published count before trusting it

**Context:** B5-1022 handed me a twin census with a pre-published figure ("exactly 12 stat
divergences") and an explicit instruction to "re-derive it with the same exclusion rather than
re-measuring the raw 140." Re-deriving confirmed the count and the field tally verbatim, but
also surfaced two announced-bonus increases at unchanged cost with no offset — Latent Telepath
(psiBonus 2→3, cost 4→4) and Power Posturing (militaryBonus 1→2, cost 8→8) — which a
count-only reconciliation would not have flagged. The count was right; the count was also
incomplete as a truth proxy.

**Lesson:** when a task gives you a pre-published count, re-derive it from raw data with the
stated exclusion rules *and then read the individual records*, because a count match proves the
arithmetic is consistent with the source but does not prove the source's classification of each
item is complete. A count can be exactly right and still conceal the most expensive class of
error in the dataset (here: inflation bugs invisible to every existing gate). The re-derivation
is cheap relative to the cost of shipping an uncorrected power creep, so do both: count *and*
read.

**Action:** re-derive pre-published counts from raw data; after the count matches, spot-check
the individual items in the highest-risk class (here: enhancements whose bonus rose) rather than
stopping at the count.
