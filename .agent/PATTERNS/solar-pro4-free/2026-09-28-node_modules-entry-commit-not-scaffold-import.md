# Tracked-node_modules entry commit is not the scaffold import commit

**Context:** Assessing a repository where `node_modules/` dominates tracked file count.

**Finding:** The commit that first added `node_modules/` paths is NOT the same commit that imported the scaffold (`package.json`, `src/`). `npm install` output is committed separately, often much later. Citing the scaffold import commit as the "dependencies entered" commit is incorrect.

**Rule:** When reporting when dependencies entered a repository, use `git log --diff-filter=A -- node_modules/` to find the actual first commit that added `node_modules/` paths, not the scaffold import commit. The scaffold import brings the package manifest; `npm install` output enters later.

**Why it matters:** A removal recommendation that cites the wrong commit for when `node_modules/` entered will mislead the human about the cost and history of the cleanup. The scaffold import may be intentional; the `node_modules/` commit is the one that made them tracked.

**Reference:** B5-0921 report.
