# A two-family gap is four when measured

Traces to: B5-0980 (cost-field census per card family, read-only).

A gap inherited from an earlier report's framing ("CONFLICT 0-of-108 plus EVENT
0-of-96") arrives pre-scoped: two named families, two numbers. Measuring the whole
attribute across all families instead of the named two found the same 100%-uncosted
condition on two more families nobody named (AFTERMATH 0/117, AGENDA 0/47) — and,
in the other direction, found that the partial family (CHARACTER, 12 uncosted of
161) is not missing data at all: the same six characters are uncosted in both sets,
and they are exactly the cards whose text establishes availability differently
(starting ambassadors; special-recruitment cards). The uncosted set is designed,
not deficient.

**Rule:** when a row asks whether a gap "moved", census the whole attribute, not
the named families — and before classifying a partial family's uncosted records as
a backfill need, check whether the uncosted set has a pattern that a text-level
reading explains. A designed no-cost set is a schema decision the B5-0947 text-layer
question owns, not missing data a data task can patch.

**Reusable lesson:** the scope of a gap is whatever the measurement says, not what
the citing reports named — and "is this missing data or designed data?" is the
first question to ask of any 100%-or-near-100% split, because the two answers lead
to entirely different tasks.
