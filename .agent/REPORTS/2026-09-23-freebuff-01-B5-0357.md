# B5-0357 — Bonus-layer and expiry design (D10/D11)

**Deliverable:** `docs/proposals/d10-d11-bonus-layer-expiry-design-proposal.md`.
Proposal-only task; zero edits to `b5ccg/src/` or `b5ccg/resources/`.

## What was delivered

A complete design for replacing the permanent stat mutation in
`CharacterCard.applyStatDelta` / `FleetCard.applyMilitaryDelta` with a bonus
layer, covering all four requirements from the task row:

1. **Expiry** — `Expiry` enum on each `StatBonus`
   (`WHILE_IN_PLAY | END_OF_TURN | START_OF_NEXT_OWNER_TURN | ON_EVENT(key)`),
   swept in `GameState.advanceRound()` by owner turn-parity; leaving-play
   removes by `sourceCardId` immediately.
2. **Blanking** — bonuses carry their granting card's id; blanking the
   source removes its bonuses while the card's own printed stats still
   count (§4.3 pins this with a test).
3. **Cumulative effects** — `cumulative` flag: cumulative bonuses all add;
   non-cumulative same-source re-grants replace.
4. **Psi-from-zero** — two bonus classes (`psiFromZero` flag): generic Psi
   bonuses contribute nothing on a base-0 stat unless a specific grant is
   present, which then unlocks the stat for all bonuses (recorded
   interpretation; §4.4 pins it).

## Key findings recorded en route

* **The mutation is live behavior, not latent.** D10/D11 were written when
  enhancement bonuses had zero callers; B5-0202's effect dispatch now
  routes four real call sites through the mutating methods (enhancement
  `_FLEET`/`_CHARACTER`/`_FACTION` + the fleet+1 agenda). Census in the
  proposal §1.
* **Double-count hazard is real.** B5-0337 (leader Leadership) and B5-0339
  (assistant +1) deliberately read as computed overlays; a mutated base
  feeding those read paths can count the same bonus twice. The proposal's
  read path composes them as a separate, non-mutating term.
* **The D10 floor-at-1 is a bug, not a guard** — the proposal deliberately
  removes it (final clamp at 0; Military-0 fleets become legal), matching
  the audit's own note that Military 0 exists on printed cards.
* **Influence is excluded by design** — B5-0342 (D9) owns the
  rating-vs-applied pool; `StatKey` has no INFLUENCE member to make that
  boundary structural.
* **Implementation path:** 4 phases (introduce layer → remove mutation →
  expiry consumers → B5-0345 Tier-3 damage subsystem), each independently
  green, with 7 specified conformance tests and named risks (AI raw-getter
  divergence, sweep off-by-one timing).
