Scope: `.agent/TASK_LEDGER.md` read-only. Enumerate every row whose Task cell contains a gate clause, resolve each named prerequisite ID against actual status on disk, report three classes. Mutate nothing.

## Method

1. Parse all 312 ledger rows (id → status → Task cell text).
2. For each row, extract all `B5-\d+` IDs from the Task cell (excluding self-reference).
3. For each row that names a prerequisite, check the Task cell for satisfaction-language patterns: `gate.*satisfied`, `gate satisfied`, `satisfied YYYY-MM-DD`, `-- satisfied`, `gate (met|cleared|ok|green|done)`, `satisfies the gate`, `gate is (satisfied|met|cleared)`, `DONE -- satisfied`, `is DONE -- satisfied`, `both DONE -- satisfied`, `all DONE -- satisfied`, `claim ONLY after ... satisfied`, `own claim DONE -- satisfied`, `DONE, own claim DONE -- satisfied`, `is DONE, own claim DONE -- satisfied`.
4. Rows passing both checks (names a prereq + asserts satisfaction) are "gated rows with satisfaction claims."
5. For each named prerequisite, resolve against the actual row status on disk.
6. Also scan OPEN rows for `.agent/REPORTS/*.md` citations and verify each cited file exists.
7. Classify each finding: Class A (prereq DONE — correctly satisfied), Class B (prereq not DONE), Class C (no such row ID), Class D (missing report file).
8. Rank Class B and C by whether the gated row is otherwise claimable (OPEN, no live claim).

## Discussion

The ledger has 75 rows whose Task cell names at least one prerequisite B5-\d+ ID. Of those, 13 instances across 8 rows assert some form of satisfaction language. Every one of those 13 fails the disk-verification test: either the named prerequisite is not DONE, or the cited report file does not exist.

The false-gate class is real but concentrated: 8 of 13 findings are on 4 historical rows (B5-0317, B5-0547, B5-0551, B5-0556) that are DONE or SUPERSEDED and no longer gate active work. The other 5 are on 3 OPEN rows (B5-0606, B5-0615, B5-0616), all of which are the repair/audit chain itself — their self-references are intentional, not errors.

The one actionable false gate (B5-0606 → B5-0594, both OPEN) has been repaired by B5-0615 (gate clause rewritten to NOT satisfied, false report citation deleted).

The missing-report finding on B5-0574 is a filename transcription issue (space vs hyphen in agent_id), not a nonexistent report — the row may have been written correctly under the hyphenated form.

## Reusable lesson

A gate-consistency audit that only greps for `gate satisfied` misses satisfaction language in many forms (`-- satisfied`, `is DONE -- satisfied`, `both DONE -- satisfied`, `own claim DONE -- satisfied`) — the sweep must extract all B5-\d+ IDs from each Task cell and check every satisfaction-phrase pattern. Self-referential findings (the audit/repair task naming itself or its sibling as a prerequisite) are expected and should be annotated as such, not counted as false gates. A missing-report finding where the filename has a space-versus-hyphen transcription error is a different class from a truly nonexistent report — verify the likely-correct filename before flagging.
