## Finding-by-finding verdicts on `.agent/REPORTS/2026-09-25-solar-pro4-free-B5-0408.md`

**F1 "100% stall rate — games never converge" — ARTIFACT, corrected.** The
data (all 5 games hitting the 60s wall at rounds 4–5) replicates, but the
cause is harness throughput, not a game stall: with a 240s window the SAME
seeds complete — game 1 round 9 in 85.8s (Beta), game 2 round 11 in 138.3s
(Beta), game 3 round 16 in 163.8s (Gamma). Rounds cost ~9–14s each because
every AI action sleeps 600ms and the D6 loop generates many actions per
round. Even at 60s the stall label is wrong for completed seeds: the runner's
own 10-game sample produced 1 completed win (Gamma, round 7). No logical
consecutive-pass stall was observed in any probe. The engine terminates
normally; the 60s ceiling is the binding constraint.

**F2 "D6 not landed / single-pass-per-round is the root cause" — STALE,
contradicted by the tree.** GameController.runActionPhase IS the B5-0372
initiative-cycle loop: no per-player action cap, `setPassed(false)` un-passing
on non-pass actions, passCount reset on any non-pass, 8×playerCount liveness
cap (fired as designed, not as a per-player gate). B5-0372 is DONE on the
ledger with its own conformance section. The report's root-cause paragraph
describes the pre-0372 engine.

**F3 "Tier-3 (attack/heal/repair) not yet implemented" — STALE, contradicted
by the tree.** B5-0370/0371/0368 are DONE and the code is live
(RulesEngine.executeAttackConflictParticipant, canHealCharacter,
canRepairCard; conformance ATK/HLR sections; B5-0402 shipped the UI).

**F4 NEW finding (not in 0408): the damage subsystem is STRUCTURALLY
UNREACHABLE in AI-vs-AI games.** Observed attacks=0 heals=0 repairs=0
neutralized=0 in every probe game, and the source explains why: conflicts
resolve synchronously INSIDE the initiating action — processAction's
INITIATE_CONFLICT branch sets the active conflict, calls
resolveCurrentConflict() (AI joiners commit ambassadors, resolution runs,
aftermaths fire), then clears the active conflict — all before the action
loop resumes. The attack offer gate requires an active, unresolved conflict
at AI DECISION time; that state never exists when chooseAction() runs.
Conformance tests reach the handlers only by invoking them directly
(reflection). Damage enters only via attacks (or the B5-0309 military-loss
ambassador flip, type-scoped — all observed initiations were diplomacy/
intrigue-reward types), so heals and repairs also never fire. Consequence for
playtesting: a human at the table WILL see attacks (they act while a conflict
is active in the join window sense), but pure AI-vs-AI rounds never will.
Fix direction for a future task: either an async conflict-resolution phase
(the rulebook's separate Resolution Round) or AI attack offers evaluated
inside the resolution window. NOT fixed here (no claimed scope for engine
work).

**F5 "Zero promotions" — CONFIRMED as data, root cause corrected and
deepened.** promotes=0 across all probes too. The mechanism is live and
offered (canPromote, promotionCost, MEDIUM score max(1, 8−IC)); what starves
it is a scoring interaction: USE_ROTATE_EFFECT (assistant boost, MEDIUM 2)
outranks PASS (0), so the AI rotates supporting characters for assists in
volume (36–82 uses per game in my probes) — those same characters must be
READY for canPromote, and the sole IC member (ambassador) is frequently
rotated by Build Influence/Lead Fleet. Bootstrap interaction: with 0
promotions IC stays at size 1, promotion cost stays cheap, yet the ready-
character precondition is what fails. Recording as an AI-tuning candidate
(cap assist re-rotation, discount assists below pass, or value IC growth
higher once influence ≥ 8). NOT fixed here (ai/ out of harness scope).

**F6 "Zero agendas set" — PARSER ARTIFACT, corrected.**
HeadlessMultiRoundTest.parseLog counts `" sets agenda:"` — no engine code
ever logs that string (agendas log ` plays <Title>` / ` sponsors a hidden
agenda (face down).`). End-state inspection found agendas INSTALLED in every
deep-probe game ("As It Was Meant To Be" on 5 of 12 players), and my title-
cross-checked census counted 0–2 sponsors per game. The B5-0364 one-major
gate plus DISCARD_AGENDA offers (2–5 per game, e.g. Delta discarding Revenge)
show the agenda lifecycle live. Also: the report's "agenda victory needs 20
influence" reading is wrong on two counts — agenda win conditions are
card-keyed (INFLUENCE_20 etc. via isConditionMet), and Standard Victory
(20 + strict lead) fired on its own: Alpha won a probe game at 21.

**F7 "Initiators won 71%" — CONFIRMED** (my probes: 21 win / 12 loss and
8/8, 15/15, 3/3 per-game; consistent with winnable-initiation scoring).

**F8 "No mercenary bids / no wars" — CONFIRMED** (B5-0386 no-evidence
verdict; no tension sources in pool per B5-0354; both surfaces are
engine-ready and inert by data, not by bug).

**F9 "Aftermaths 15" — CONFIRMED** (starter decks carry 4–6 aftermaths per
race via premiere-starter-decks.json; my aftermath-free deep-probe decks
correctly produced 0 — good isolation, not a contradiction).
