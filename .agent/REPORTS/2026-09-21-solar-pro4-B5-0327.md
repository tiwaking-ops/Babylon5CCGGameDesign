# B5-0327 — Phase-aware gating + initiative display

**Date:** 2026-09-21  
**Agent:** solar-pro4 (solar-pro4:free)  
**Scope:** `b5ccg/src/b5ccg/ui/` — `MainWindow.java` only  
**Gates:** Java 6 gate clean, compile ✓, conformance 81/81 PASS, smoke PASS

## Changes

### F6 — Phase-aware enablement

`refresh()` now differentiates phases beyond the prior ACTION-only gating. Button enablement uses a `phaseAllowsAction` predicate:

```java
boolean phaseAllowsAction = (phase == GamePhase.ACTION
    || phase == GamePhase.CONFLICT_RESOLUTION
    || phase == GamePhase.AFTERMATH
    || phase == GamePhase.DRAW);
```

- **ACTION**: all buttons available as before (sponsor/promote/build-influence/play/in initiate).
- **CONFLICT_RESOLUTION**: play/in initiate buttons enabled (player can respond to an active conflict).
- **AFTERMATH**: play/in initiate enabled (post-conflict card effects).
- **DRAW**: play/in initiate enabled (draw-phase card play if the rules allow).
- **SETUP / END_ROUND**: all action buttons disabled (no player actions available).

Previously only `GamePhase.ACTION` unlocked the action buttons; the other phases left them permanently off even when the controller had work for the human.

### F8 — Initiative display

A new `JLabel initiativeLabel` added to the toolbar between the support/oppose buttons and the status label. `refresh()` sets it to the active player's name with a `(you)` tag when it is the human's turn:

```
Initiative: Jerrie  (you)
```

Shows `"Initiative: —"` during initial construction and `"Initiative: <name> (you)"` once `onStateUpdate` fires. The full initiative chain remains on the board panel; this is a status-bar summary.

## No engine/model edits

## Notes

- `initiateConflictButton` is disabled whenever `selectedCard` is a non-conflict card; `playCardOnlyButton` is disabled whenever `selectedCard` is a conflict card. This prevents the user from pressing the wrong button for the card type.
- When a conflict is already active and the user selects another conflict card, both buttons disable (can't start a second conflict). This matches the prior single-button behavior.
- The `phaseAllowsAction` list is intentionally narrow (4 of 6 phases); SETUP and END_ROUND are excluded because no human actions are legal in those phases per the current controller implementation.
