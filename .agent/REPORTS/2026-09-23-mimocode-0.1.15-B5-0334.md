# B5-0334 — Saturday Night RPG (saturdaynightrpg.co.uk) B5CCG column-code decode

## Scope and method

Task: decode the integer-code columns of the SNRPG B5CCG deck-builder table
(Set / Rarity / Type / SubType + the six mark columns) against known cards and
the canonical rulebook. **Report-only, no JSON / no src/ edits.**

Live evidence in this session:

- Single polite fetch of the SNRPG card table:
  `saturdaynightrpg.co.uk/index.php?pageName=Cardgames&type=B5CCG&var=B5CCG`
  (~1.1 MB HTML, `pageName=Cardgames` returns a server-rendered table with no
  JS — the `collection` `<table id="collection" style="display:none">` block
  has the full 23-column schema). Cached at
  `b5ccg/out/scratch/snrpg/snrpg-b5ccg.html` (git-ignored scratch).
- `requests` + `BeautifulSoup` parsed 1729 data rows; unique KeyIDs. JSONL
  dump at `b5ccg/out/scratch/snrpg/snrpg-rows.jsonl`. Scratch + deleted at
  session end per B5-0204/B5-0307/B5-0333 precedent (no permanent artifact
  under the canonical repo).
- Cross-reference against our two card files
  (`b5ccg/resources/cards/premiere.json` 446 records, `deluxe.json` 383 records,
  total 829) and the canonical rulebook (`BABYLON5_CCG_RULEBOOK.md`,
  *do not edit body*).

## Table schema (verbatim from the page)

| # | Column        | Encoding          |
|---|---------------|-------------------|
| 0 | `KeyID`       | int (1..1733; 1729 distinct values used) |
| 1 | `Name`        | free text (1712 distinct titles; 11 multi-row reprint pairs) |
| 2 | `Rarity`      | int code (1..6) |
| 3 | `Type`        | int code (1..10) |
| 4 | `SubType`     | int code (44 distinct values) or empty string |
| 5..9 | `Diplomacy`/`Intrigue`/`Psi`/`Leadership`/`Military` | floats (printed as e.g. `0.0`) |
| 10 | `Cost`      | int or `0` (never blank) — the printed orange influence-cost bubble (per `BABYLON5_CCG_RULEBOOK.md:1054`) |
| 11 | `BoldText` | free text (trait vocabulary) |
| 12 | `EffectsText` | full card text |
| 13..18 | `ConspiracyMarks` / `DestinyMarks` / `DoomMarks` / `StrifeMarks` / `ShadowMarks` / `VorlonMarks` | int (count of printed marks on the card face; rulebook §Marks, "Any marks initially possessed by a character will be shown here") |
| 19 | `FlavorText` | free text |
| 20 | `Set`        | int code (1..9; 9 distinct values used) |
| 21 | `Race`       | int code (1..10) |
| 22 | `ShowInFilter` | always `0` (dead metadata; consumed by nothing) |

The table does not include a printable set-name or rarity-name column — the
integer codes encode BOTH the printed expansion-set and the printed card kind
in opaque numeric form.

**Distinct finding**: Our model uses a single `faction` enum
(HUMAN/MINBARI/CENTAURI/NARN/NEUTRAL/NON_ALIGNED/ANY), but the SNRPG DB
distinguishes Race 5 (Non-Aligned), 8 (Drakh), 9 (Shadow), 10 (Vorlon) as
**separate races**, with Race 6 reserved for race-agnostic cards. For a
future data task, the model would need to grow a `race` field (or expand
`faction`) to absorb these — B5-0315's cost-field design is the cleanest
seam; race could be a parallel field.

### Six mark columns

These are the literal counts of printed marks on the card face, per
rulebook §Marks: "Any marks initially possessed by a character will be
shown here for reference."

| Column            | Rulebook mark name | Mark class |
|-------------------|--------------------|------------|
| `ConspiracyMarks` | Conspiracy         | Psi Corps expansion (set 5+6) |
| `DestinyMarks`    | Destiny            | generic |
| `DoomMarks`       | Doom               | generic |
| `StrifeMarks`     | Strife             | grants +2 damage during attacks (rulebook :693) |
| `ShadowMarks`     | Shadow             | Shadow-vs-Vorlon opposing mark (rulebook :158, :1094) |
| `VorlonMarks`     | Vorlon             | Shadow-vs-Vorlon opposing mark |

In the SNRPG table, marks are stored as cardinal int counts (default 0;
values seen: 1, 2, 3). The 2/3 values always appear on CHARACTER (Type 3)
cards — there are 16 rows with mark=2 and 4 rows with mark=3 across all six
columns, all on CHARACTER. CONFIRMED: mark column = "count of this mark
printed on this card's face" — not "minimum mark count required to play"
(those requirements appear in the card text, not in the column values).
