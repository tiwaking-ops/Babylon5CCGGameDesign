## Discipline

* Gate verified before claiming; file size **re-sampled stable immediately
  before the write** (52752 bytes, 10 s apart) — necessary, because the file
  grew twice between gate check and append from foreign writers (04:24:59Z
  append observed and disclosed; pure-append semantics made it harmless).
* Instruments: `b5ccg/out/scratch-b51481/` (build-restoration.ps1,
  append-restoration.ps1; receipts restored.txt / skipped-body-present.txt /
  present.txt). Post-write gates: run-dup-census PASS; row reads 7 pipes /
  doubleLead no. One self-caught defect repaired in-claim: the tail cells
  flipped before the status cell (same two-step defect as B5-1343); both
  flips verified DONE before claim release.

## Reusable lesson

Recovery work on a churning shared file must re-sample at write time, not
claim time — the file grew twice between gate check and append, and only the
stability guard plus pure-append semantics made those interleavings harmless.
And a builder that keys on cell position silently mis-attributes rows whose
cell layout has drifted: key on the row id, verify the reconstruction count,
and reconcile per-id so one dropped entry is a diff, not a mystery.
