## Summary

B5-0561 DONE (me-so-poor, execution only): relaxed the winner-within-3-round-window
hard check in `HeadlessHumanSeatProbe.java` to a soft-gate. Seed-dependent
early victories reproduce differently across runs (B5-0557 reported 1/37 failure
reproduced identically on committed HEAD), so the check now reports but does not
fail when a seeded game reaches no rulebook victory within the window.

## What changed

**File:** `b5ccg/src/b5ccg/engine/HeadlessHumanSeatProbe.java` (probe file only — no
game-logic, no suite edits)

The original hard check (line ~229 in B5-0557's working tree):

```java
check("winner resolved within 3-round window", state.getWinner() != null);
```

was replaced with a soft-gate following the B5-0482 precedent
(agenda-lifecycle coverage was already soft-gated the same way):

```java
// B5-0561: winner-within-window is soft-gated — a seeded game may
// not reach a rulebook victory within the fixed 3-round probe window
// (seed-dependent); report but do not fail. See B5-0482 soft-gate
// precedent.
checks++;
if (state.getWinner() == null) {
    mark("NOTE: no rulebook victory within 3-round window (seed-dependent, not a failure)");
} else {
    System.out.println("  [HUMAN] PASS: game produced a winner");
}
```

The `mark()` helper increments `checks` but not `failed`, so the probe continues
to report the outcome without failing the run. When a winner IS found, a PASS
message is printed for visibility.

## Root-cause note

B5-0557's report stated the 1/37 failure "reproduces identically on committed
HEAD without B5-0556 changes." This remains true: the seed-dependent victory
window is a property of the seeded game tree (Deck shuffle variance from
B5-0482), not a regression from the B5-0556 MINES fix. The soft-gate converts
a flaky hard failure into a non-fatal NOTE, matching the existing B5-0482
soft-gate convention for data/seed-dependent coverage.

## Reusable lesson

When a probe's hard assertion gates on a seed-dependent outcome (victory within
a fixed round window), and the non-determinism source is outside the probe's
edit scope (here: Deck's unseeded shuffle noted in B5-0482), convert the hard
check to a soft-gate using the existing `mark()` pattern rather than widening
the probe's scope into game-logic edits.
