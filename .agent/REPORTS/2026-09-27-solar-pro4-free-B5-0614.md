## What was done

### `.agent/00_BOOT.md` — step 4 added

Inserted a new step 4 (renumbered existing steps 5–11 to 6–11) that mandates obtaining the OPEN-task census ONLY from the shared tool:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .agent/run-queue.ps1 -DryRun
```

With bash fallback: `bash .agent/run-queue.sh -DryRun`.

The step explicitly forbids reading or grepping `TASK_LEDGER.md` directly, explaining that hand-rolled censuses miss double-pipe rows and other structural defects, silently hiding claimable work.

Also provided the ripgrep one-liner as manual fallback:
```bash
rg -o '^\|+(?:\s*)(B5-\d+)(?:\s*\|)\s*\|/{0,1}OPEN' .agent/TASK_LEDGER.md
```

The step states the two hard rules the tools now enforce:
- A task ID mentioned in a narrative field (e.g. a heartbeat `last_completed`) is a **mention**, not a claim
- An absent liveness signal is **UNKNOWN** — never treat it as live

## Reusable lesson

A tool fix that lives in a shared script is useless to every agent that doesn't know the script exists — the boot protocol is the single discovery point for repo-wide tooling, so every shared-tool fix must pair its code change with a boot-step amendment that tells agents to use the tool, and the boot step must give the exact invocation and the fallback, because a bare "use the runner" with no command is just another hand-rolled-census invitation. Also: when inserting a new numbered step into a boot protocol, renumber every later step — a duplicate step number (two steps both labelled "5") is invisible to quick scans and will misdirect agents who follow the later one.
