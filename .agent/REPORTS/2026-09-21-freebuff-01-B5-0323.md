# B5-0323 — cost plumbing (B5-0315 follow-through)

Agent: `Buffy (deepseek-v4-flash)`. Toolchain: `javac 1.8.0_292`. Date: 2026-09-21.

## Deliverables (files in claim scope)

- **`model/Card.java`** — `cost` field, `int`, default 0 (B5-0311 C1: no card
  carries the key today), with `getCost()`/`setCost()`; negatives clamp to 0,
  matching the class's existing mutator style.
- **`engine/DeckLoader.java`** — `parseCards` hydrates the optional `"cost"`
  key after `buildCard` (absent → 0; unparseable → 0). No constructor churn
  across the nine card subclasses. **No invented prices**: the two data files
  are untouched; all 829 cards keep cost 0 until the later backfill task.
- **`engine/RulesEngine.java`** — `promotionCost` base is now
  `ch.getCost()` (the seam B5-0321 reserved); new `recruitCost`/`canRecruit`
  implementing rulebook §Sponsor: card cost, doubled for characters loyal to
  a different race, neutral characters at no additional cost.
- **`engine/GameController.java`** — `RECRUIT_CHARACTER` branch now requires
  `canRecruit` and spends `recruitCost`; a rejected recruit logs and leaves
  the card in hand. At the current all-zero costs, observable behavior is
  byte-for-byte what it was before this task (by design).
- **`ai/AIPlayer.java`** — the recruit offer is gated by `canRecruit`, so the
  AI never offers an action the engine would reject (liveness discipline from
  B5-0302/B5-0321).
- **`engine/HeadlessConformanceTest.java`** — new CST section, 13 checks:
  default-0 and negative-clamp contract; recruit cost composition (own race,
  other-race doubling, neutral free); canRecruit (hand membership,
  affordability); the live recruit path (exact spend + zone move); promotion
  affordability flipping with influence (`cost + IC member` = 3); loader
  hydration of an explicit cost and of an absent key. Suite: 61 → **74
  checks, all PASS on first run**.

## Design notes

- The loader-level hydration point was chosen over threading `cost` through
  every card constructor: one change site, zero signature churn, and the
  B5-0315 schema (`cost` = non-negative integer, sponsorable types) is
  honored identically for any type since `Card` is the base class.
- `promotionCost` and `recruitCost` remain separately computable (the
  rulebook's "sponsor discounts do not carry to promote" clause) — they share
  the base + doubling logic but add different terms.
- Build Influence's fixed 3-influence is intentionally untouched (B5-0315 §2.4).
