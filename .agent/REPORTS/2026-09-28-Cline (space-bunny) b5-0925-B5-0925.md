## 4. `RUN_TESTS=1` — measured, not assumed

The row asked which classes `RUN_TESTS=1` actually invokes. Read from
`b5ccg/compile.sh`, which names exactly two, in this order:

1. `b5ccg.engine.HeadlessConformanceTest`
2. `b5ccg.engine.HeadlessSmokeTest`

That is the whole of the wired gate. **`b5ccg/compile.bat` contains no
`RUN_TESTS` branch at all** — so on Windows the two classes must be invoked by
hand. That asymmetry was not written down anywhere before and is now in the
README.

Eleven further headless classes exist under `b5ccg/src/b5ccg/engine/` (thirteen
total, counting the two wired). Three of them say in their own line-10 header
that they are *not* wired into `RUN_TESTS`:
`HeadlessAIDifficultyContractTest`, `HeadlessParticipationGatesProbe`,
`HeadlessWarConflictProbe`. `docs/playtest-guide.md` §6 is the authoritative
list.

```

java -cp out b5ccg.engine.HeadlessConformanceTest   exit 0   CONFORMANCE SUITE PASSED (643 checks)
```

One benign warning appears on JDK 8
(`bootstrap class path not set in conjunction with -source 1.6`) and is
documented as expected rather than left as a surprise for the next reader.

**Limitation, stated:** `b5ccg/compile.sh` itself could not be executed on this
host — `bash` resolves to a WSL relay that fails with
`execvpe(/bin/bash) failed: No such file or directory`. The two classes its
`RUN_TESTS` branch would have invoked were run directly instead, which is the
same gate by the same classpath. The shell wrapper's control flow is read, not
executed.
