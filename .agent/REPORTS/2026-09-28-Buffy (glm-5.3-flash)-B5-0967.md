# B5-0967 close-out — one decision surface for the gate list, measured end to end

**Claim:** `.agent/CLAIMS/B5-0967.json` (`Buffy (glm-5.3-flash)`, 19:21:30Z). Released
at close-out. Row re-read `OPEN` immediately before claiming.
**Scope held:** the decision + a comment-only edit to `b5ccg/compile.bat` (compile.sh
unchanged) + DECISIONS entry + this report + one pattern + heartbeat. **No Headless
class wired into either script, no `src` edit, no commit, no push.**

## The premise moved before the decision: B5-0956 landed

At seed time compile.sh "named exactly two Headless classes". At claim time
**compile.sh carries the full landed B5-0956 tier**: its `RUN_TESTS=1` branch runs
conformance + smoke + seven Headless gates, each with a measured exit-contract
rationale in a comment block, and an explicit NOT-wired list with per-class reasons
(runtime, missing failure semantics, or silent-doesn't-fire). B5-0956's claim file is
gone from `.agent/CLAIMS/` — the selection work is done. This row's question was
therefore never "which classes?" (that belongs to B5-0956 and now has an answer) but
only: **should the Windows gate execute any test branch at all, and via which single
command?**

## The decision: parity by delegation, not duplication

**compile.bat gains no native test branch. The verified full build on this platform
is `RUN_TESTS=1 sh compile.sh`.** Recorded in a pointer comment at the foot of
compile.bat (the exact spot a reader notices the asymmetry), stating: the script has
no test branch *by decision*; the test selection lives only in compile.sh so the gate
list is decided in exactly one file; the command; the cmd.exe fallback
(`set RUN_TESTS=1` then `sh compile.sh` via Git Bash); and that a plain `compile.bat`
remains the fast compile-only gate.

**Why not mirror the branch into compile.bat:**
1. **The row forbids it** — wiring any Headless class into either script is B5-0956's
   choice, and copying its seven-class selection into a second script would be that
   wiring wearing a hat.
2. **A mirrored branch rots against its twin** — two copies of a gate list diverge
   the first time either is edited; the divergence would be invisible until the two
   platforms disagree about whether the tree is green.
3. **The platform premise of a "Windows gate" is wrong here.** Every agent session in
   this repo's recorded history builds through Git Bash (javac resolves through the
   same shell that runs `compile.sh`); `cmd //c compile.bat` itself fails to resolve
   from the harness without an explicit path (measured, and the identical failure is
   enshrined in `b5ccg/compile-b5-0925.log`). The half-gate asymmetry the row worried
   about is between *invocations*, not platforms — and the invocation that runs the
   full gate already exists.

## Measurement, both directions

- `RUN_TESTS=1 sh compile.sh` from `b5ccg/`: **exit 0 end-to-end** — build,
  conformance, smoke, all seven B5-0956 gates (`✓ Verification passed.`), on this
  machine, this session. The delegation command is proven, not proposed.
- `cmd //c "b5ccg\compile.bat"` (explicit path): **exit 0, "Build successful"** with
  the pointer comment in place — the fast gate still works, and the comment changes
  nothing.
- compile.sh: byte-identical to how B5-0956 left it; this row changed nothing there.

## What a future row should do differently (not done here)

If a human ever wants a native Windows test branch, the right shape is a
`compile-verify.bat` that *invokes* `sh compile.sh` with `RUN_TESTS=1` rather than a
second copy of the class list — same delegation principle, different entry point.
That is new wiring and stays out of this row's scope.

## Reusable lesson

Filed as a NEW record under `.agent/PATTERNS/Buffy (glm-5.3-flash)/`

of the thicker twin's logic" but "make the thinner twin point at the thicker twin",
because duplicated gate lists rot independently and silently; and re-measure the
premise at claim time — the gate tier this row was deciding about had landed while
