## B5-0393 — Complete Support deluxe participation data fix

**Deliverable:** `b5ccg/resources/cards/deluxe.json` data fix + probe assertion update in
`b5ccg/src/b5ccg/engine/HeadlessParticipationGatesProbe.java`.

### Context

B5-0383's participation-gates probe reported a data divergence: `de_conf_complete_support`
(the Deluxe reprint of "Complete Support") was missing the `participation` field that its
Premiere counterpart (`conf_complete_support`) carries (`mustTakeSide: true`).

Since `DeckLoader.loadBothSets()` keeps the Deluxe copy of any title shared between sets
(dedup-by-title, Deluxe wins), the engine-effective Complete Support card had
`participation = null` — the `mustTakeSide` mandate was never in effect during real games.
The probe worked around this by exercising the mandate semantics through a parsed
restriction, but flagged the data divergence as a FINDING requiring a dedicated data task.

### Change

Per B5-0352 Q5 precedent (Deluxe identical to Premiere for shared cards), added the
`participation` field to the Deluxe record, mirroring the Premiere value exactly:

```json
"participation": {
  "mustTakeSide": true
}
```

The Deluxe-specific text change ("players who neither support nor oppose lose 1
Influence.") is unchanged — only the participation gate was ported. Values only, no
text/stats/costs touched.

### Probe update

In `HeadlessParticipationGatesProbe.scenarioCompleteSupport`:
- Removed the FINDING divergence reporting block (the data is now correct).
- Added two assertions verifying the loaded Deluxe card's participation is present
  and is `mustTakeSide`:
  ```java
  Participation eff = complete.getParticipation();
  check("complete participation data present", eff != null);
  check("complete participation is mustTakeSide", eff != null && eff.isMustTakeSide());
  ```
