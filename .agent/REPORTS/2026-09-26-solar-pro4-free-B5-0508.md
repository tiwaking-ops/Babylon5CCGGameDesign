## What changed

### AIPlayer.java — easyChoose pass threshold

File: `b5ccg/src/b5ccg/ai/AIPlayer.java`, line 471 (method `easyChoose`).

Before:
```java
if (legal.size() > 1 && rng.nextInt(10) < 3) return GameAction.pass();
```

After:
```java
if (legal.size() > 1 && rng.nextInt(10) < 2) return GameAction.pass();
```

The EASY player passes when `rng.nextInt(10)` returns 0, 1, or (before) 2 — i.e.
3/10 = 30% direct pass probability. After the retune, it passes when the roll is
0 or 1 — i.e. 2/10 = 20% direct pass probability. This is the floor-0.20 change:
the minimum pass rate (when the uniform-over-green-tail contributes nothing, e.g.
exactly 2 legal non-pass actions) drops from ~30% to ~20%.

The tail behavior (uniform pick from non-pass legal actions) is unchanged — only
the direct-pass threshold moved. The expected pass rate with 2 legal plays drops
from ~53% (30% + 70% * 1/3) to ~43% (20% + 80% * 1/3), still inside the
0.20–0.70 band.

## Reusable lesson

When retuning a probabilistic AI parameter, widen the contract band in the SAME
claim that changes the parameter — a retune without a band update leaves the
contract test asserting against the old floor, which either fails (if the new rate
drops below the old band) or passes vacuously (if the new rate still falls inside
the old band but the band no longer reflects the design intent). The contract test
is the spec; the parameter change is the implementation; they must move together.
