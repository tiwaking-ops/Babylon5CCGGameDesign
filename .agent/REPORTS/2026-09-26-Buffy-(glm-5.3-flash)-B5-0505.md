# B5-0505 — Smoke fix slice (highest-severity B5-0495 finding)

Task: smallest fix for the highest-severity 0495 finding, in whatever scope the
defect lives; gate green. Both 0495 triages (mine and the concurrent session's)
converged on the same defect: the HeadlessSmokeTest step-[5/5] hand-membership
checker exempts only 3 payload types while the AI action set emits 8 more types
whose payloads live outside the hand. Defect scope: harness fixture
(b5ccg/src/b5ccg/engine/HeadlessSmokeTest.java) — no game-logic change, so no
new conformance section is required by the row; the existing suite still
guards all engine behavior.

## 1. The fix (one hunk, checker only)

HeadlessSmokeTest.java step-5 card check: replaced the 3-type negated
exclusion chain with an explicit `boolean slotPayload` allow-list of exactly
the types whose `getCard()` payload is NOT a hand card, each verified against
its AIPlayer offer site and GameAction factory:

| Type | Payload actually is | Offer site (AIPlayer.java) | Factory (GameAction.java) |
|---|---|---|---|
| BUILD_INFLUENCE | no card (was exempt) | — | — |
| PROMOTE_CHARACTER | IC member (was exempt) | — | :109 |
| USE_ROTATE_EFFECT | assistant (was exempt) | — | — |
| DISCARD_AGENDA | agenda IN PLAY | :345 | :125 |
| REVEAL_AGENDA | agenda IN PLAY | :350 | factory family |
| HEAL_CHARACTER | IC/supporting character | :227/:232 | :105 |

| ATTACK_CONFLICT_PARTICIPANT | committed participant | :217 | :100 |
| REVEAL_CONTINGENCY | placed contingency | :390 | :155 |

DELIBERATELY NOT exempted (payloads ARE hand cards, checker still guards
them): REPLACE_AGENDA (hand replacement agenda, :364), PLAY_CONTINGENCY (hand
contingency, :382), plus all pre-existing hand-card paths (PLAY_CARD,
RECRUIT_CHARACTER). The twin triage's :392 flag ("reveal-agenda") is
REVEAL_CONTINGENCY's loop header line; the offer is at :390 — same family,
covered. Contingencies-in-hand double-offer protection comments (:377–379)
were read during the audit and are unaffected.

## Reusable lesson

Fix residency checkers at the TYPE level with an explicit payload-residency
table (payload source per action type), not by patching individual call
sites — the same audit that builds the table proves the exemption set is
complete, and the table documents WHY each type is exempt for the next
payload-family author. Supersedes-never-rewrite chain:
2026-09-26-verifier-exclusion-lists-must-track-new-payloads.md (superseded by
2026-09-26-supersedes-verifier-exclusion-lists.md; core lesson stands, and
B5-0505 is its application).
