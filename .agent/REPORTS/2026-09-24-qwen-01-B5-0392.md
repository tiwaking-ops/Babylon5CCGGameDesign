## Additional work performed during close-out

### Bug: `Conflict.canCommitCard` leadersIncluded gate rejected valid characters

**Root cause:** The original `canCommitCard` used `part.allowsCardType(c)` in the
leadersIncluded condition. `allowsCardType` applies BOTH the cardTypes check AND
the fleetSubtypes check. For a `CharacterCard`, `allowsCardType` returns false
because CHARACTER is not in the `cardTypes` set (which is `["FLEET"]`). The code
then entered the leadersIncluded block to check whether a fleet was alongside —
correct behavior for the "refuses a character with no allowed fleet" case. However,
after the alongside check passed (fleet found), execution fell through to the
final `if (!part.allowsCardType(c)) return false;` which **re-rejected** the
character because CHARACTER is still not in cardTypes.

**Fix:** Two changes in `Conflict.canCommitCard`:
1. Changed the leadersIncluded guard condition from
   `!part.allowsCardType(c)` to `!part.getCardTypes().contains(c.getType())`
   — this tests ONLY the cardTypes membership, not the fleet subtypes. This
   correctly distinguishes "char not in allowed card kinds" (enter the alongside
   check) from "char fails the full filter" (which should not reject a
   leadersIncluded character).
2. Changed the trailing `if (!part.allowsCardType(c)) return false;` to
   `else if (...)` so that when a character enters and passes the leadersIncluded
   alongside-fleet check, it is NOT re-rejected by the standard cardTypes filter.

The net effect: a CharacterCard committing alongside an allowed fleet under
`leadersIncluded:true` now correctly passes after the alongside check, instead of
being rejected a second time by the trailing `allowsCardType`.

### Bug: `Conflict.canJoinConflict` extra `isPlayableBy` check on war conflicts

**Root cause:** The war-conflict branch of `canJoinConflict` included an extra
`initiatorRace.isPlayableBy(playerRace)` check beyond the `isAtWar` check. This
was leftover from an earlier draft and was incorrect — war conflict participation
is gated solely by the warfare state in `TensionMatrix`, not by card playability
(which only governs which player can play cards of a given faction).

**Fix:** Removed the `initiatorRace.isPlayableBy(playerRace)` clause from the
war-conflict branch of `canJoinConflict`.
