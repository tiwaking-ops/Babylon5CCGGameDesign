# B5-0311 — card JSON data audit

Agent: `freebuff-01`. **No JSON was edited** — this task is report-only;
all findings below are proposals for the human/overseer to schedule.
Dataset: `b5ccg/resources/cards/premiere.json` (446 records) +
`deluxe.json` (383 records) = **829 records**, matching the 829 cards the
B5-0201 smoke test loads.

## Conformance results (verified by exhaustive grep/awk sweeps)

1. **Identity** — zero duplicate `id`s across both files; id prefixes are
   self-consistent (`de_` appears exactly 383 times, all in deluxe.json;
   0 in premiere.json).
2. **Base schema** — all 829 records carry all 9 base keys
   (`id,title,type,subtype,rarity,faction,set,imageKey,text`).
3. **Per-type keys complete and consistent:**
   CHARACTER ×161 (diplomacy/intrigue/psi/leadership/isAmbassador),
   FLEET ×80 (military), LOCATION ×21 (influencePerRound),
   ENHANCEMENT ×78 (5 bonus fields), CONFLICT ×108 (conflictType +
   influenceReward), AGENDA ×47 (winCondition + isMajorAgenda),
   AFTERMATH ×117 (triggerCondition), GROUP/EVENT base-only.
   No missing keys anywhere; no stray keys except one singleton (P2).
4. **Enum values all valid** — 9 `type`s (map 1:1 to `CardType`), 4
   rarities (COMMON/UNCOMMON/RARE/FIXED), 2 sets, 7 factions
   (ANY/NEUTRAL/NON_ALIGNED + 4 races; enum has VORLON unused by data).
5. **`conflictType` vocabulary** is exactly the four rulebook types:
   DIPLOMACY 47, INTRIGUE 40, MILITARY 17, PSI 4.
6. **`triggerCondition`: 117/117 present, 14 distinct values** —
   WON 15, LOST 33, PARTICIPANT 10, MILITARY_PARTICIPANT 16,
   WON_MILITARY 10, WON_INTRIGUE 6, WON_DIPLOMACY 4, LOST_MILITARY 4,
   LOST_INTRIGUE 4, LOST_DIPLOMACY 4, INTRIGUE_PARTICIPANT 4,
   DIPLOMACY_PARTICIPANT 4, WON_PARTICIPANT 1, ANY 2.
   **Every value parses correctly** under
   `AftermathCard.isEligible`'s substring semantics (WON/LOST + type +
   PARTICIPANT AND-combine; `ANY` always eligible), including compound
   forms — no data value relies on the fall-through.
7. **`winCondition`** is a clean 3-value vocabulary: INFLUENCE_20 ×39,
   MOST_INNER_CIRCLE ×4, MILITARY_SUPREMACY ×4.
8. **Numeric sanity** — influenceReward all 1..4 (winner-gain only);
   diplomacy 1..8; leadership 1..7; psi 0 ×115 and 1..5 ×43. No
   negative or absurd values. No placeholder (`"text":"text"`) or empty
   texts in either file.
9. **subtype/faction consistency** — CHARACTER/FLEET/LOCATION race-named
   subtypes match their `faction` field except 4 intentional-looking
   divergences: 2× `CHARACTER_VORLON` with `faction NEUTRAL`
   (`char_kosh_naranek`, `de_char_kosh_naranek`), 2× `LOCATION_HUMAN`
   with `faction ANY` (`loc_proxima_iii`, `de_loc_proxima_iii` — note
   Earth/Mars themselves are faction HUMAN, so this is a deliberate
   convention for "Earth-Force-allied" locations).

## Defects found (proposals; no edits applied)

**P1 — `de_agenda_seizing_advantage` carries `"set":"PREMIERE"` while
living in deluxe.json.** Its `de_` prefix, its placement, and all 382
siblings say DELUXE. This is not cosmetic: `DeckLoader` reads the `set`
field (`CardSet.valueOf(...)`, line ~157) so the card loads mis-set.
*Proposal: one-field edit to `"DELUXE"` — the only record-level JSON fix
the dataset needs.* (Requires a JSON-edit task per B5-0311's charter.)

**P2 — `de_event_armistice` has a singleton `"timing":"ANY"` key** that
no other record carries and no code consumes (DeckLoader reads known keys
only; the key is silently ignored). Its timing lives in the text already.
*Proposal: drop the key (or document it if it foreshadows a future
field).*

**P3 — `de_am_secondary_experience` under-encodes its trigger.**
`subtype AFTERMATH_WON_PARTICIPANT` vs `triggerCondition "WON"`; its text
requires participation as a supporter. `isEligible("WON", …)` would let a
non-participant play it. *Proposal: set `triggerCondition` to
`WON_PARTICIPANT` — already supported by `isEligible` — or align the
subtype.*

## Structural proposals (schema-level; larger than one-line edits)

**P4 — no `cost` field anywhere** (0 matches, both files): confirms audit
D13 — the double-cost rule for sponsoring other races' loyal characters
is unimplementable, and deck-construction costs cannot be validated. Also
connects to B5-0312's deck-cut finding: without any deck-cost/quota
dimension, file-order deck filling is arbitrary. *Proposal: add a cost
field in a future schema revision (task to be scheduled by the human; the
task charter forbids JSON edits).*

**P5 — race restrictions live in free text.** 72 card texts contain
"… only" restrictions (e.g. locations "Centauri only"), and 2 cards
diverge from subtype/faction (see #9). The only machine gate is
`Faction.isPlayableBy`, so most rulebook restrictions are unenforceable.
*Proposal: an optional structured `restriction` field in a future schema
revision.*

**P6 — `triggerCondition` is free text with a permissive parser.** All 14
current values parse correctly today, but `isEligible` falls through for
unknown tokens — a future typo silently degrades to "always eligible".
*Proposal: when the JSON-edit gate opens, validate the vocabulary; a
strict parser is a model-side task (AftermathCard).*

**P7 — psi interplay (data-side note, no defect).** 115 characters have
psi 0; the rulebook ("Psi cannot be raised from a base of 0 unless a card
specifically increases Psi") is unenforced in `CharacterCard.applyStatDelta`
(audit D11). Nothing to fix in the data; recorded for the model-side task.
