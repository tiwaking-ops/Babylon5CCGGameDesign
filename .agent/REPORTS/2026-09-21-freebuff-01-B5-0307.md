# B5-0307 — CardEffect dispatch (implements the B5-0203 recommendation)

Agent: `freebuff-01`. Toolchain: `javac 1.8.0_292`. Scope: `engine/` only
(claim `.agent/CLAIMS/B5-0307.json`). No `model/` change was needed: the
existing `CharacterCard.applyStatDelta` and `FleetCard.applyMilitaryDelta`
methods became the application path, so the previously-dead bonus getters now
have live callers.

## Root design decision: id-keyed registry, not text parsing

`b5ccg/resources/cards/*.json` carries structured bonus fields for
enhancements (`militaryBonus` etc.) and a `winCondition` key for agendas, but
plain-text effects (events, conflicts, agendas ongoing) have no structured
fields. Parsing English card text in code was rejected as unmaintainable;
instead `CardEffects` holds **static maps keyed on card id exactly as in the
JSON**. Every entry was data-verified against the JSON at write time (ids,
magnitudes, and texts cross-checked with grep). Adding a card effect = adding
one map entry. Unknown ids never crash: events fall back to the old generic
draw-1, everything else degrades to "held in play".

## What now actually runs

* **Enhancements** (previously zero callers of any bonus getter):
  `_FLEET` subtypes attach to the strongest own fleet via
  `applyMilitaryDelta(JSON militaryBonus)` — covers `enh_mass_drivers` +3,
  `enh_stealth_technology` +3, `enh_energy_mines` +2, `enh_censure` −2 (+Deluxe);
  `_CHARACTER` subtypes attach to the strongest own character (ambassador
  included) via `applyStatDelta(JSON bonuses)` — e.g. `enh_power_posturing`
  (+1 Mil, +3 Lead); `_FACTION` with `militaryBonus` boosts all own fleets
  (e.g. `enh_assault_troops` +1); LOCATION income ids (`enh_exploitation`)
  are held and paid out in `startRound`. GLOBAL/BABYLON5/other are held in
  play (logged); their text effects remain future work.
* **Events**: exact effects for `merchandising_b5` (+1 inf),
  `destiny_fulfilled` (+2), `secret_vorlon_aid` (+2), `intrigues_mature` /
  `contact_with_vorlons` / `contact_with_shadows` (draw 2), `balance` /
  `for_the_common_good` (all players +1). Unknown ids keep the generic draw-1.
* **Conflicts**: loser penalties for `dishonor`/`condemn_deportations`/
  `affirmation_of_peace`/`loss_of_support` (−1 inf), `hate_crime` (−2),
  discard penalties for `bio_weapon_discovery` (2) and `loss_of_support` (1),
  winner steal for `raid_shipping` (+1 from loser). Winner influence reward
  remains in `RulesEngine.resolveConflict` (untouched).
* **Agendas**: `higher_calling`/`servants_of_order` (+1 inf per round, the
  Deluxe `servants_of_order` gated on 2+ Inner Circle per its text),
  `a_rising_power` (+1 on Diplomacy win), `total_war`/`order_above_all`
  (fleets +1 on play). One-time agendas replay-on-replay is not possible:
  `applyAgendaOnPlay` runs only at play time.

## Known limits (recorded, not silently dropped)

* Enhancement **target selection** is owner-side strongest-valid-target;
  opponent-targeting (e.g. Censure should attach to an *opponent's* fleet)
  needs a target-selection concept the model does not carry yet (same root
  as audit findings D2/D14).
* Non-numeric texts (cancel/rotate/switch-side/look-at-hand/conditional
  Morden+1, faction restrictions like Isolationism's Psi protection) are
  unimplemented; they need side/timing context beyond this task.
* `_CHARACTER` enhancements with `militaryBonus` (Power Posturing) apply the
  leadership bonus; its "your Military conflicts gain +1" clause is a
  conflict-level modifier — future work with conflict modifier plumbing.
* Only conflict cards with clean loser penalties are registered; the rest
  resolve with the winner reward only, as before.
