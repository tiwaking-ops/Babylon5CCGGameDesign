# B5-0459 — Agenda non-appearance triage (B5-0447 anomaly)

**Verdict: DONE — report-only static audit, zero source edits.**

## Question

B5-0447 reported 0 agenda plays across 10 games and flagged the anomaly as
unexplained (not a pass-bias stall — 9 of 10 games had natural terminations).
This audit determines whether the cause is threshold-unreachability, an AI
offer/scoring gap, an engine refusal, or a harness-parser artifact. Grounded in
the tree (grep + code trace + conformance-suite evidence), not speculation.

## Findings (ranked Confirmed/Refuted)

### H1 — CONFIRMED (primary): parser token `" sets agenda:"` never matches any engine log

`HeadlessMultiRoundTest.parseLog()` (line 278) searches for:

```java
else if (content.contains(" sets agenda:")) { ag++; }
```

But the engine **never logs** this string. The actual agenda-related log
messages (all in `GameController.java`) are:

| Event | Line | Log token |
|---|---|---|
| Sponsor (face-up) | 616 | `"X plays AgendaCardName"` |
| Sponsor (face-down) | 629 | `"X sponsors a hidden agenda (face down)."` |
| Reveal | 363 | `"X reveals hidden agenda CardName — it takes effect immediately."` |
| Discard | 315 | `"X discards agenda CardName."` |
| Replace | 335 | `"X replaces OldAg with NewAg (Leader rotates)."` |

None contain `" sets agenda:"`. The agenda counter is therefore **structurally
incapable of incrementing** — it will read 0 whether or not agendas are played.

This is the same bug class as B5-0413 (promotions): the promotions counter
previously searched for `" promotes:"` with a colon, which the engine never
logged (the engine emits `"X promotes CardName to the Inner Circle (...)"`).
B5-0413 fixed it by changing the token to `" promotes "` (space-delimited).
The agenda counter was never similarly aligned.

### H2 — CONFIRMED (secondary): low agenda draw rate limits opportunities

The multi-round deck builder (`HeadlessMultiRoundTest.buildFactionDeck`,
line 295) adds exactly **2 agenda cards** to each 60-card deck. Players draw
4 cards at setup and 1 per round (draw Phase). Over a 4–16 round game, a
player draws 5–17 cards from a 60-card deck.

Expected agenda draws per game:
`2 × (drawn / 60) ≈ 0.17–0.57`

This means many games will not draw an agenda at all. Even when one is drawn,
the AI must also have `p.getAgenda() == null` (no agenda already in play) to
sponsor it. This is a contributing factor but is masked entirely by H1 — even
if agendas are played, the count is wrong.

### H3 — REFUTED: AI offer/scoring gap

The AI **does** score and offer agenda actions. Evidence:

1. **AES conformance section** (`testAESScoring` in HeadlessConformanceTest,
   17 assertions, 176/176 PASS) verifies:
   - MEDIUM takes a win-on-play agenda when `agendaProximityScore` returns 9
     (influence 18+) over a free recruit scoring 5.
   - MEDIUM declines a far agenda (proximity 3 at influence 6) and recruits
     instead.
2. `agendaProximityScore` (AIPlayer.java:886) returns `p.getInfluence() / 2`
   for INFLUENCE_20 agendas, capped at 9. At the starting influence of 4 this
   is already 2, beating PASS (which scores 0 for MEDIUM, see line 607).
3. The AI offers agenda sponsorship via `GameAction.playCard(c)` when
   `p.getAgenda() == null` and `c instanceof AgendaCard` (AIPlayer.java:189–196).
4. `scoreActionMedium` (line 518–521) and `scoreActionHard` (line 710–711)
   both score agenda plays via `agendaProximityScore − cost`.

The AI scoring path is live and correct — **not** the cause of zero agenda
plays.

### H4 — REFUTED: engine refusal

The engine correctly allows agenda sponsorship:
- `RulesEngine.canSponsorAgenda` (referenced at GameController:610) checks
  the one-major rule and the one-agenda-per-player constraint.
- `applyGenericCardPlay` (line 624–632) sponsors the agenda, sets
  `p.setAgenda(...)`, and logs the play.
- The D12 conformance section (testD12, 5 assertions) verifies major-agenda
  blocking and standard-victory interaction.

No engine-side refusal prevents agendas from being played.

## Conclusion

The 0/10 agenda count is a **harness-parser artifact (H1)**, compounded by a
**low-draw-rate secondary factor (H2)**. The AI correctly offers and scores
agendas (H3 refuted); the engine correctly sponsors them (H4 refuted). Every
agenda play is invisible to `parseLog()` because the parser searches for a log
token (`" sets agenda:"`) that the engine never produces.

## Proposed fix (for a future slice — NOT implemented here)

The parser should count any agenda-related log line. Two options:

1. **Minimal** — broaden the match to catch all agenda log variants:
   `content.contains(" agenda")` would match "sets agenda", "discards agenda",
   "reveals hidden agenda", "sponsors a hidden agenda", and
   "gains N influence from agenda". BUT it would NOT match the
   face-up sponsor log `"X plays AgendaCardName"` (which contains no "agenda"
   substring). This is fragile.

2. **Robust** — track card types in the parser: when `"X plays CardName"` is
   seen, look up the card by title in the loaded pool and check
   `CardType.AGENDA`. This requires a title-to-card index but catches all play
   paths including face-up sponsorships. This follows the precedent of the
   promotions fix (B5-0413) which correctly changed the token after discovering
   the engine's actual log format.

**Recommendation**: Option 2, deferred to a future harness-fix slice. The
current 0/10 count should be treated as untrustworthy in B5-0447 and any
downstream balance analysis until the parser is corrected.

## Reusable lesson

A harness parser that searches for a log token without first verifying the
engine actually emits that exact string will silently undercount zero —
indistinguishable from "no events occurred." The promotions counter (B5-0413)
was fixed by this exact class of bug; the agenda counter has never been
similarly aligned. **Before trusting a zero count, verify the parser matches a
real log line by grep-ing the engine source for the search token.** See also
[[b5-0413]].
