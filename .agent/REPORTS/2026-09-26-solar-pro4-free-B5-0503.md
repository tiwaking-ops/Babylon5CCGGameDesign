## What the 0428 proposal expected

B5-0428 (`docs/proposals/2026-09-25-solar-pro4-free-B5-0428.md`) is a
proposal-only task: it defines a three-rating station-influence model (human /
shadow / vorlon, 0-100, inert from day one) on `Babylon5Station` (B5-0340), and
records the design's sources, sinks, end-of-round condition-2 checks, Shadow-War
trigger wiring, tension-matrix interaction, and the B5-0354 Support-Babylon-5
no-rewire trap. It explicitly recommends a readout-first wiring order: wire
readout tasks B5-0427 and B5-0429 against inert ratings first, add card hooks
later.

The proposal's anticipated sources (what would MOVE the ratings):

1. **Capture** — first capture of the station by a faction, +1 rating for that
   faction's influence axis. Source type: event/card hook.
2. **Presence bleed** — passive presence on the station leaks influence to the
   dominant presence faction. Source type: event hook (passive/continuous).
3. **Event-card hooks** — faction-drawn event cards that reference the station
   and apply a rating delta. Source type: card-effect hook.
4. **Tension pressure** — tension-matrix state (B5-0376) contributes a
   read-only soft modifier to influence movement. Source type: derived state
   read.

The proposal's anticipated sinks (what would LOSE or CAP ratings):

1. **Loss** — station loss/battle outcomes drain the losing faction's rating.
   Sink type: event/card hook.
2. **Decay** — passive decay per round toward a baseline. Sink type: passive
   per-round tick.
3. **Counter-influence hooks** — faction actions that push back against another
   faction's rating. Sink type: card-effect hook.
4. **Tension loss-of-face** — tension-matrix outcomes that cost influence. Sink
   type: derived state interaction.

The proposal's anticipated end-of-round condition-2 checks (placeholders, to be
refined by design-intent class):

1. Shadow-War-active threshold.
2. Vorlon-active threshold.
3. Human-secured threshold.
4. Uncontested threshold.

The proposal's anticipated Shadow-War trigger wiring: read-only state derived
from the three ratings (e.g., shadow rating above threshold → Shadow War active),
not a card-action trigger.

The proposal's anticipated tension-matrix interaction: read-only soft modifier
from B5-0376, applied at the read path rather than as a direct mover.

The B5-0354 trap: Support-Babylon-5 card must NOT rewire station influence;
kept isolated per the proposal's explicit warning.

## Gaps (proposed but not implemented)

All source/sink/condition-2/trigger elements are in the "later phase" gap. This is
expected and consistent with the 0428 proposal's readout-first sequencing: the
proposal defined the design but explicitly deferred engine implementation to a
later card-hooks slice (B5-0437, gated on B5-0432 + B5-0436). No implementation
has landed for any of these.

The one element that IS landed from the proposal is the design document itself
(B5-0428 DONE) and the readout-first sequencing (B5-0427/B5-0429 DONE).

   first captures the Babylon5 station (derive from B5-0340 station ownership + a
   "first capture" flag per faction), grant +1 to that faction's influence rating;

   scope engine only. Not a separate task — folded into the 0437 slice.

3. **Event-card hooks** — no implementation. One-line slice proposal: faction event

   the card text requires it). This may need a model edit (new card field) — scoped

4. **Tension pressure** — no implementation. One-line slice proposal: at the
   influence-read path, apply a soft modifier from B5-0376 tension-matrix state to

5. **Loss sink** — no implementation. One-line slice proposal: when the station is

6. **Decay sink** — no implementation. One-line slice proposal: per-round passive

7. **Counter-influence hooks** — no implementation. One-line slice proposal: faction

8. **Tension loss-of-face** — no implementation. One-line slice proposal: tension-

## Verdict

The 0428 proposal is fully consistent with what has landed: the proposal was
proposal-only (no src edits), defined the three-rating model as a design concept,
and explicitly sequenced readouts first (B5-0427/B5-0429 DONE) before any
card-hooks engine slice. No implementation has landed for any source, sink,
condition-2 check, or Shadow-War trigger — and that is EXPECTED, not a gap or
defect. The only "remainder" elements are the deferred later-phase hooks that the
proposal itself scheduled after readouts, and they are all pending B5-0437
(gated on B5-0432 + B5-0436).

No new task is created by this audit. The verdict is: consistent, no defects, move on.

## Reusable lesson

A proposal-only design task (like B5-0428) that explicitly sequences readouts
first and defers engine implementation creates a docs-level audit trail that a
later coverage audit can verify without touching src/. The audit should map each
proposal element to its expected implementation phase and check whether the
sequencing was honored — not whether the implementation exists (it was never
promised yet).
