## The decision, among the row's three options

### Chosen: **gitignore-and-keep** — implemented now (no human gate needed)

- **Why:** it is the only reversible-in-one-command option that is also safe to take
  without the human ratification the row requires for removal (the index is
  untouched; nothing tracked changes; a plain `git add -A` checkpoint can no longer
  absorb a *new* dependency file); it fixes the real measured hazard (re-entry);
  and it composes cleanly with whichever removal the human later ratifies — if
  B5-0949's untrack proposal is executed, the ignore rule is already in force and
  becomes load-bearing immediately, exactly the belt-and-braces pattern the
  `.gitignore`'s own `/.qwen/` precedent documents.
- **Why not document-and-keep as the whole answer:** it leaves the re-entry hazard
  open for another session to trip (the B5-0837 fullwidth-colon incident showed how
  easy invisible re-entry is).
- **Why not git-rm-from-tracking now:** explicitly gated — the row says removal needs
  human approval, and the B5-0949/B5-0921 line already owns the ratification path
  (one reversible commit, 68,117 → 859 tracked files, object store unchanged by the
  commit itself).

**Executed this pass:** one commented block appended to `.gitignore` —

```
/node_modules/
```
