# B5-0302 — one-conflict-per-faction-per-turn, enforced by the engine

Agent: `freebuff-01`. Toolchain: `javac 1.8.0_292` (`-source 6 -target 6` gate).

## Rule

Rulebook, section **Conflicts**: *"Each faction may normally initiate only one
conflict per turn."* (BABYLON5_CCG_RULEBOOK.md line 546.) The Confrontation
step (line 365) phrases the per-player side: *"each player … may declare one
conflict."* Pre-fix, nothing in `model/`/`engine/` tracked or enforced this;
the AI only self-restrained (B5-0202 Fix #1) and `RulesEngine.canInitiateConflict`
had **zero callers** — a human or a refactored AI could initiate every action.

## Design

- **Turn = round boundary in this engine.** `GameController.runGame()` calls
  `state.advanceRound()` after every action round, so per-turn state resets
  there. A per-player marker set on `GameState` cleared in `advanceRound()`
  implements exactly the rulebook's "per turn" semantics for this engine.
- **Enforcement lives in the engine, not the AI.** The gate is
  `RulesEngine.canInitiateConflict` (now wired into the INITIATE_CONFLICT
  branch), so *any* caller — human UI, future AI, future agenda-driven
  initiation — is subject to it.
- **Liveness pairing (important).** A rejected INITIATE_CONFLICT leaves the
  card in hand, so an AI that still offers conflicts would retry forever
  (`useAction()` floors at 0, the action isn't PASS, `passCount` never
  accumulates → infinite loop). The AI offer guard in
  `AIPlayer.buildLegalActions` is therefore **load-bearing**, not cosmetic:
  with it, a blocked player's legal list loses conflict offers and the
  player passes, terminating the loop.

## Changes (5 files)

1. **`model/GameState.java`** — `Set<Player> conflictsInitiatedThisTurn`
   (identity semantics; `Player` has no equals/hashCode), cleared in
   `advanceRound()`; `hasInitiatedConflictThisTurn(p)` /
   `markConflictInitiated(p)`.
2. **`engine/RulesEngine.java`** — `canInitiateConflict` now returns false
   when `state.hasInitiatedConflictThisTurn(p)` (B5-0302 comment).
3. **`engine/GameController.java`** — INITIATE_CONFLICT branch checks
   `rules.canInitiateConflict(...)` first: on rejection it logs
   "cannot initiate X — one conflict per turn." and `break`s (card stays in
   hand, no action consumed beyond the normal `useAction()`); on acceptance
   it calls `state.markConflictInitiated(p)` before constructing the
   conflict. The previously dead legality check is now the enforcement point.
4. **`ai/AIPlayer.java`** — one-line condition extension in
   `buildLegalActions`: conflict offers also require
   `!state.hasInitiatedConflictThisTurn(p)`.
5. **`engine/HeadlessConformanceTest.java`** — new **CPT** section, 5 checks
   (see below). Suite: 32 → **37 checks**.

  conflict per turn; none exist in current card data. When one is added,
  `markConflictInitiated` should move behind a counter, not a boolean.

  modeled; when it lands it should route through the same gate.
