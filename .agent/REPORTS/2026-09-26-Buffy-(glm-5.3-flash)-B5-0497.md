# B5-0497 — Near-class enhancement wiring triage

Static audit only per row text: reads of `b5ccg/src/b5ccg/` source and the
B5-0477 census report. No code edits, no harness runs, no data edits.

## Baseline: the landed Censure path (B5-0468 seam + B5-0473 wiring)

Play-time one-shot: `CardEffects.applyPlayEnhancement` `_FLEET` branch
(CardEffects.java:221+) resolves an explicit target (findPlayerByName +
fleetById), grants `card.toAttachedBonus(MILITARY)` into the **victim
Player's** bonus registry keyed to the victim fleet id
(Player.addBonus, Player.java:224), read passively at
`FleetCard.getEffectiveMilitary` (FleetCard.java:45) via
`Player.effectiveStat` (Player.java:316). Lift is
`removeBonusesBySource(cardId)` (Player.java:264). Floor support exists
since B5-0486 (BONUS_FLOORS, min-1 on the Censure pair).

## Proposed slices (at most two, per row)

**Slice 1 — shunned pair** (engine + HeadlessConformanceTest section only):
extend the B5-0473 explicit-target path to CHARACTER hosts with a
multi-stat attached penalty (registry grants + `effectiveStat` read —
printed min 0 needs no floor), plus a discard-on-heal reactive map at
`executeHealCharacter` (id-keyed, lift via `removeBonusesBySource`).
Conformance hooks: victim-registry grant per stat, attacker-registry clean,
all four stats reduced, heal discards the enhancement and lifts the penalty,
no-regression on the Censure path.

**Slice 2 — mines + energy_mines together** (engine + suite only):
one shared reactive damage-on-attack hook at `executeAttackConflictParticipant`
consuming (a) faction-held mines and (b) the energy_mines self-attached
fleet. Energy_mines' +2 Military self-attach rides the existing no-target
`_FLEET` grant path. Grouping is deliberate: the two pairs share the single
reactive trigger, so one slice lands both at half the hook cost.
Conformance hooks: attacker damaged when attacking a mines holder,
energy_mines self-bonus present, reactive fires for the self-attached host,
no double-trigger.

**Deferred (not proposed, recorded with reasons):** isolated (zone-lock
constraint machinery), forced_commitment (opponent action-economy class),
overworked (unrotate-cost plumbing does not exist; two new subsystems).
None of the three can reuse the Censure consumption path materially;
they should wait for a positional/constraint sweep of their own.

## Notes

* The 0477 flagged "(minimum 1)" interpretive gap for Censure itself is
  already RESOLVED by B5-0486 (BONUS_FLOORS min-1 on enh_censure /
  de_enh_censure) — no remainder there.
* All five near-class pairs are opponent-**mentioning** but only shunned,
  mines, and energy_mines are opponent-**targeted** in effect; isolated,
  overworked, and forced_commitment constrain their OWN side or the action
  economy, which is why they rank last on reuse of the opponent-target seam.
* Data check (static, from the 0477 census table): all pairs exist in both
  sets as deluxe reprints with byte-identical texts — no data task blocks
  slices 1 or 2.

## Reusable lesson

Rank wiring work by which side of the grant/trigger boundary it lives on:
play-time grants into the existing registry are near-free, reactive hooks
cost one call site each — and pairs sharing a trigger should land in one
slice.
