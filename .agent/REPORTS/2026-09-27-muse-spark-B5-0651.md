## Deliverable

`.agent/tools/census-crosscheck.ps1`, strictly read-only (reads ledger, CLAIMS,
HEARTBEATS; writes nothing). For every ledger row it computes each tool's
verdict by that tool's own logic and diffs the two across five rules:

* `row-visible` — run-queue Get-LedgerRows tolerant anchor plus split-parts
  floor vs ledger-query rowRegex.
* `status` — run-queue first-ID plus first-status-token cell scan vs
  ledger-query cell-after-ID.
* `pipe-shape` — run-queue silent multi-lead tolerance vs ledger-query
  doubleLead flag. Any multi-lead row is a disagreement by construction.
* `norm-name` — both verbatim Get-NormName copies executed separately, so a
  future one-sided edit turns red.
* `claim-liveness` — run-queue Test-LiveClaim (newest of started_utc-or-mtime
  and owner heartbeat, per-claim ttl_min, corrupt reads live, future reads
  live) vs ledger-query verdict (fixed TtlMinutes, corrupt reads unclaimed,
  no-heartbeat reads UNKNOWN).

Disagreements print as `ID | rule | run-queue: value | ledger-query: value`.
Exit 0 agree, 1 disagree, 2 input missing — mirroring
`validate-heartbeats.ps1`. The one documented deliberate divergence (B5-0649
row: owner with no heartbeat reads UNKNOWN vs claim-age fallback) is reported
like any other; the checker does not silently forgive it.
