## Instrument classification (the row's second question)

* **PowerShell 5.1 `Set-Content`/`Out-File`/`Add-Content` and
  `[System.IO.File]::WriteAllLines` default to CRLF on Windows** and rewrite
  or extend the file in their own ending — the dominant flipper class. The
  B5-0777-era DECISIONS record (line ~5249/5262 of the working file) already
  caught `WriteAllLines` doing this to the ledger; the same class is the
  likely agent of the DECISIONS flips.
* **bash heredoc/`echo >>` write LF** (my earlier DECISIONS appends and
  heartbeats were LF at write time).
* **str_replace-style editors inherit the file's bytes** for untouched
  regions.
* Because DECISIONS.md is now uniformly CRLF, no per-line ownership boundary
  is currently observable; the boundaries this row was asked to identify
  were erased by the second flip. The churn itself is the finding.

## The smallest convention statement (named, not applied)

> **Every append to a shared coordination file samples the file's CURRENT
> dominant line ending immediately before the write and matches it;
> appends are byte-appends (open-for-append + exact bytes), never

inventoried the file and edited nothing else in it.

**Reusable lesson:** line-ending churn in an append-only file is caused by
whole-file rewrites by instruments with different newline defaults — an
append that samples and matches the current dominant ending is invisible to
byte history, and any tool that rewrites the file wholesale is the defect,
not the appends.
