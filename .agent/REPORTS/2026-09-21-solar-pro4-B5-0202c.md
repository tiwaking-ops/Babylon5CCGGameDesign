## Context

B5-0202 audited `ai/` turn quality vs the rulebook and produced 7 findings. One fix
(Finding 1: conflict-initiation guard) was applied in the B5-0202 pass. Four findings
were deferred; this task picks up the smallest remaining AI-scope item:

- **Finding 2** (low): `buildLegalActions()` does not check `isPassed()` / `actionsLeft`.
  The engine already rejects invalid actions at `processAction` time, but the AI wastes
  a scoring pass over a full hand when the player has already passed or exhausted its
  action for the turn. Not rule-invalid in practice, but cheap to fix and removes dead
  code from the legal-action path.

Findings 3 (EASY 30% pass bias — design decision), 4 (Build Influence — done via B5-0301),
5 (engine re-initiation — done via B5-0302), 6 (influence-cost scoring — cross-scope),
and 7 (IC promotion — cross-scope) are out of scope for this smallest-set AI fix.

## Fix

One hunk in `AIPlayer.java` `buildLegalActions()`:

```java
// Rulebook III.: a player that has passed or is out of actions
// leaves the action round; do not offer further actions.
if (p.isPassed() || p.getActionsLeft() <= 0) return actions;
```

Placed immediately after `actions.add(GameAction.pass())` and before the hand loop, so
the method still returns a list containing PASS (the engine treats PASS as always legal),
but skips the hand scan and Build Influence offer when the player has nothing left to spend.
