# B5-0313 — harness deck-construction fix

Agent: `freebuff-01`. Scope honored: **`HeadlessSmokeTest.java` (test
harness) only — zero game-logic files touched.** Toolchain `javac 1.8.0_292`.

## Problem being fixed

B5-0312's headline finding: all 108 conflict cards are `faction: ANY` and
the first sits at filler position #42 in file order, while the smoke deck
builder took only the first ~20 fillers — so conflicts never entered any AI
deck and the smoke scenario could never exercise the conflict pipeline
(B5-0309 sides, aftermaths, loser penalties, damage: all suite-verified only).

## Changes (1 file, harness only)

`HeadlessSmokeTest.buildFactionDeck` now builds in three passes:

1. Own-faction cards (unchanged, file order).
2. **Quota guarantees: 12 conflicts + 2 agendas per deck**, taken in file
   order from the full pool — guaranteed ahead of fillers, so the cut can
   no longer exclude them.
3. Neutral/ANY fillers as before, capped at 60.

Plus an **ambassador guarantee** found necessary during verification:
`GameController.setupGame()` extracts a player's ambassador from the
opening hand only, and `Deck` shuffles in its constructor — so the
ambassador often missed the 4-card opening hand and *every* conflict
resolved 0 vs 0 (no auto-added ambassador). The harness now pins the
faction ambassador to the draw-pile top via `Deck.addToTop(...)` after
construction (mirroring `GameController.findAmbassador`'s own rule for
what counts as the ambassador). This stays a harness change: the game
logic is untouched; the harness simply deals a scenario that includes the
ambassador, as a real player's deck effectively would.
