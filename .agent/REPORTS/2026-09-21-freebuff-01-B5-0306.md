# B5-0306 — compile.sh Windows+MSYS path bug (fixed) + suite wiring

Agent: `freebuff-01`. Scope: `b5ccg/compile.sh` only (script-only task,
"always runs parallel" per ledger rules).

## Root cause

The old script did `ROOT="$(cd "$(dirname "$0")" && pwd)"` and passed
`$ROOT/src`-style arguments to javac. Under Git Bash/MSYS, `pwd` returns a
**POSIX path** (`/c/temp/...`), but javac on this system is the **native
Windows** toolchain, which cannot read `/c/...` paths — so the script failed
for agents running it through sh while `compile.bat` (native `%~dp0`) worked.
The file also carried CRLF line endings, which break stricter shells and made
the script fragile even where paths resolved.

## Fix

Rewrote `compile.sh` (LF endings):

* `cd "$(dirname "$0")"` once, then use **relative paths** (`src`, `out`,
  `resources`) for find/javac/cp — no path translation is ever needed, so the
  script works identically under sh, bash, and MSYS/Git Bash, and on
  Linux/macOS.
* Same build contract as before: `-source 6 -target 6 -encoding UTF-8`,
  resources copied into `out/`, non-zero exit on failure.
* Added an opt-in verification section: `RUN_TESTS=1 sh compile.sh` runs
  `HeadlessConformanceTest` (B5-0308) and `HeadlessSmokeTest` (B5-0201)
  after the build and propagates failures. Default remains off — a plain
  `sh compile.sh` is unchanged in behaviour (fast compile gate), so other
  agents' workflows are not surprised.

## Verification

* Clean rebuild (`rm -rf out`) → `✓ Build successful`, 36 source files.
* `RUN_TESTS=1 sh compile.sh` → conformance suite 21/21 PASS, smoke test
  PASSED, `✓ Verification passed.`, exit 0.
* `file compile.sh` → "Bourne-Again shell script … UTF-8 text executable"
  (LF confirmed; the pre-fix file was "with CRLF line terminators").
* `compile.bat` untouched (it was never broken).
