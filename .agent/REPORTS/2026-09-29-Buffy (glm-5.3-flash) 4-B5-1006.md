# B5-1006 — Remove the `nul` reserved-name file at the repo root (DONE)

## Forensics first — the content named the creator

The file could not be read by .NET even through the device namespace
(`FileStream was asked to open a device that was not a file` — the hazard
class confirmed by exception message), but **MSYS `cat` read it**. The 142
bytes are `findstr` stderr:

```
FINDSTR: Cannot open I:/
FINDSTR: Cannot open ResolveConflict
FINDSTR: Cannot open C:\temp\projects\Babylon5CCGGameDesign\b5ccg\src\*.java
```

Verdict: a Windows `findstr` symbol census over the engine sources (the
B5-0969 census family) was run **with output redirected to `nul` from an MSYS
shell** — cmd discards the stream, MSYS created a regular file named `nul`.
The mangled `I:/` argument shows the command was already malformed before the
redirect. Content preserved at
[tmp-scans/nul-file-2026-09-29.txt](tmp-scans/nul-file-2026-09-29.txt).

## Action — delete, not move (and why)

The content is pure error output of a broken command with zero evidentiary
value beyond the quote now preserved; an untrackable hazard has no business
remaining on disk. Preservation of the content satisfies the reversibility
concern the row attaches to moving.

Git history checked per the row: `git ls-files --error-unmatch nul` fails and
`git log -- nul` is empty — **never tracked**, the plain untracked class, not
the worse tracked-reserved-name class. No `.gitignore` line added at all: the
removal is the fix, and the creator is documented here.
