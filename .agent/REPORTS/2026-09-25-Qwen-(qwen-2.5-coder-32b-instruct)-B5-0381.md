# B5-0381 — Contingency UI improvement (DONE)

## What was done

Improved the B5-0381 contingency reveal control in `b5ccg/src/b5ccg/ui/MainWindow.java`
(ui/ scope only — no model/, engine/, ai/, or data edits).

The solar-pro4:free close-out (2026-09-25) left the reveal button always revealing the first
unrevealed contingency from the deterministic list. This improvement lets the human player
**choose** which placed contingency to reveal via a `JComboBox<String>` selector, matching the
pattern already established for the conflict target selector (B5-0325 F2).

### Changes

1. **Field**: Added `private JComboBox<String> contingencySelector` alongside the existing
   `revealContingencyButton` (line 36).

2. **Creation**: The selector is instantiated with an initial `(none)` item, disabled by
   default, with a maximum size of 180×24 — mirroring `targetSelector`'s sizing pattern.

3. **Button listener**: Changed from `placed.get(0)` to `contingencySelector.getSelectedIndex()`
   (with bounds checking), so the button reveals the player's **chosen** contingency rather than
   always the first one. The `canRevealContingency` gate and `submitHumanAction` pipeline are
   unchanged.

4. **Toolbar**: Added `contingencySelector` to the toolbar immediately before
   `revealContingencyButton` (after `revealAgendaButton`), with a 4-pixel strut for visual
   separation.

5. **Refresh**: Updated `refreshContingencyRevealControl()` to populate the selector with one
   item per placed contingency, labeled `<title> (under <host>)` so the player can see which
   host the contingency is attached to. The selector is enabled when there are placed
   contingencies; the button is enabled only when at least one unrevealed contingency passes
   the `canRevealContingency` gate. Tooltip shows the unrevealed count. The null-human path
   clears and disables both controls.
