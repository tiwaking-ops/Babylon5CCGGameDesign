# B5-0377: AI Tier-1/Tier-2 slice scoring

**Date:** 2026-09-25 **Agent:** solar-pro4:free **Claim:** `.agent/CLAIMS/B5-0377.json` (released)

## Summary

Added 27 AI-scoring conformance assertions across 3 new test sections (LEAD-AI, AGL-AI, CON-AI) to `HeadlessConformanceTest.java`, plus 3 lines in `AIPlayer.buildLegalActions()` to fix two bugs the scoring assertions exposed: the generic `playCard(c)` path was offering invalid `ContingencyCard` and non-sponsorable `AgendaCard` actions that the dedicated loops already cover.

## Changes

### `b5ccg/src/b5ccg/engine/HeadlessConformanceTest.java`

- **LEAD-AI** (6 checks): MEDIUM and HARD score LEAD_FLEET pairs by unused Leadership; both tiers deterministically pick the highest-Leadership legal leader. Verifies Leadership-0 pair is offered but not picked when a better leader exists; no fleet → no LEAD_FLEET offer.
- **AGL-AI** (6 checks): MEDIUM and HARD score agenda lifecycle — REPLACE by proximity (`agendaProximityScore`), DISCARD low when no replacement exists, REVEAL by proximity. Tests displace the current agenda blocks the generic play path and influence 10 blocks Build Influence, so the lifecycle action is the only non-pass action available.
- **CON-AI** (6 checks): MEDIUM and HARD score PLAY_CONTINGENCY (2 MEDIUM / 1.5 HARD) and REVEAL_CONTINGENCY (2 MEDIUM / 2.0 HARD). Tests tie-breaking: MEDIUM breaks PLAY/REVEAL tie by list order (PLAY first); HARD picks REVEAL (2.0 > 1.5).

### `b5ccg/src/b5ccg/ai/AIPlayer.java`

- `buildLegalActions()` generic `playCard(c)` path now skips `ContingencyCard` (the dedicated loop below already offers `playContingency`/`revealContingency`) and `AgendaCard` when an agenda is already set (the sponsor check would refuse at execution time; lifecycle actions cover those cases instead). Before this fix the scoring assertions were failing because the builder was offering invalid actions that scored higher than the actions being tested.
