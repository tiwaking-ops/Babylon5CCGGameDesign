# B5-0348 Report — Hand filtering + cost sort + playable highlight

## Summary

Added hand filtering, cost-based sorting, and playable-card highlighting to `HandPanel` + `MainWindow`. ui/ only, no engine/model changes.

## Changes

### HandPanel.java

- **Type filters** (9 checkboxes: Character, Fleet, Conflict, Agenda, Aftermath, Event, Enhancement, Group, Location) — hide cards whose type is unchecked
- **Faction filters** (8 checkboxes: Human, Minbari, Centauri, Narn, Neutral, Non-Aligned, Vorlon, ANY) — hide cards whose faction is unchecked
- **Sort modes** (3 radio buttons: insertion order, cost ascending, cost descending) — reorder visible cards by cost when sorted
- **Playable highlighting** — cards that cannot be afforded by the human player are drawn with a 50% black overlay, grayed text, and the green affordability dot suppressed
- **Show-dimmed toggle** — when turned off, unaffordable cards are rendered normally (still filtered, just not dimmed)
- **Click handling** — skip invisible cards when computing click targets; selectedIndex tracks the original unfiltered hand position

### Affordability logic (`cardPlayable`)

Uses `RulesEngine.canRecruit(Player, CharacterCard)` for in-hand characters and `RulesEngine.canPromote(Player, CharacterCard)` for supporting-role characters. Non-character cards are playable if their faction is playable by the human and the card is in hand.

### MainWindow.java

- Added filter/sort panel to toolbar (titled border "Filter / Sort")
- Wired all 17 filter checkboxes + 3 sort radio buttons + show-dimmed toggle to HandPanel methods
- `refresh()` passes `RulesEngine` + `Player` to `handPanel.update()` for live affordability
- Added `makeTinyCheckBox()` helper for compact filter UI

## Design notes

- Filtering is purely visual — hidden cards remain in the hand and are still playable via buttons
- Sorting rearranges only the visible subset; hidden cards are not shown in any position
- Dimming uses `RulesEngine` affordability checks, which are already unit-tested in the conformance suite (CST section)
- Backward-compatible: existing `update(List<Card>)` overload preserved for callers that don't pass rules/player
