## Verification (concurrent-writer conditions, isolation method used)

The shared working tree was mid-flight on B5-0338 (another session under this
same agent_id — its in-flight AMT section held the shared conformance suite
red: 7 of 131 failing, all in D1/AMT aftermath asserts, a section unreachable
from card data). The standard RUN_TESTS=1 gate was therefore not meaningful
for a data-only change, so verification used an isolation gate:

1. `git archive HEAD src` → compile `javac -source 6 -target 6` (HEAD code,
   no working-tree WIP) → exit 0.
2. Run HEAD classes against the **working-tree** resources:
   `java -cp "out/scratch/classes;resources" b5ccg.engine.HeadlessConformanceTest`
   → **81/81 PASS** (includes the B5-0336 PAR ×22 section, which hydrates
   participation objects through the real loader path).
3. Same classpath smoke test → **PASS**, 446 cards loaded.
4. Zero `B5-0336:` loader warnings across both runs — all six new
   participation objects parse with clean, recognized vocabulary.
5. Scratch classes/extract deleted after the runs (git-ignored `out/`).

Owed follow-up: one full `RUN_TESTS=1` run of the shared tree once B5-0338
lands, to record a green gate that includes the new data plus all landed
enforcement. No interaction between this data and the aftermath WIP is
possible (different loader keys, different code paths).
