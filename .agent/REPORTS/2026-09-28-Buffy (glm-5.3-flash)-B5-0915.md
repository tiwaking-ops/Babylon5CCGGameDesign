## Why the Windows gate has no test path

`b5ccg/compile.bat` was read in full: it compiles
(`javac -source 6 -target 6 -encoding UTF-8`), copies resources with
`xcopy`, prints `Build successful`, and exits 0 — **no `java` invocation
and no test branch of any kind**. `b5ccg/compile.sh` carries the identical
compile+copy body plus the optional `RUN_TESTS=1` block (the B5-0308
wiring) that runs HeadlessConformanceTest then HeadlessSmokeTest and
propagates failure.

**Verdict: omission by history, not a deliberate platform split.** B5-0308
wired the verification block into compile.sh only; no DECISIONS entry ever
restricted the Windows gate to compile-only. Meanwhile B5-0699, B5-0737,
B5-0747, B5-0900 and B5-0805 all cite a gate of "compile.bat green plus
RUN_TESTS=1 green" — on this platform that is necessarily an sh-side
execution, so the gate as written is **platform-ambiguous**.

## Minimal change to give compile.bat the same switch (NOT applied)

Append an opt-in block after the resource copy:

```bat
if defined RUN_TESTS if "%RUN_TESTS%"=="1" (
  java -cp "%OUT%" b5ccg.engine.HeadlessConformanceTest || exit /b 1
  java -cp "%OUT%" b5ccg.engine.HeadlessSmokeTest || exit /b 1
)
```

About six lines, no new files, default-off like compile.sh. Deliberately
**not** done here: this row forbids compile-script edits; the change needs
its own authorized row (and it would alter the platform-ambiguous gate
wording semantics for checkpoint rows, which deserves an explicit decision).

## Reusable lesson

**A number quoted three times is a memory, not a measurement**: when rows
cite a figure (643 checks, 643/643) without re-running, the honest census is
to execute the harness once and count its output lines strictly — the
verification cost is ~20 seconds and it converts an inherited number into a
measured one (it held this time; the check exists for the time it does not).
