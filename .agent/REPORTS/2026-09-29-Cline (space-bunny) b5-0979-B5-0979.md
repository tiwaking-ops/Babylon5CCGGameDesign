## Second finding — B5-0966's recommendation 1 does not work as written

This is the part worth carrying forward. The B5-0966 report's top recommendation is
to repair the mojibake by *"3 rounds of `cp1252 -> utf-8` to a fixpoint (3 rounds),
verified by the same zero-remaining-marks check"*. I ran that recipe. **It does not
reach a fixpoint**, and it fails quietly rather than loudly:

| Recipe | Lines changed | Lines reaching fixpoint | Marks remaining (of 1,504) |
|---|---|---|---|
| `s.encode('cp1252').decode('utf-8')` as prescribed | **124** of 1,081 | **0** | **1,358** |
| `latin-1` variant | 0 | 0 | 1,504 |
| C1-aware inverse (below) | **1,081** | 1,081 | **0** |

Anyone running the report's recipe would file a *partial* repair that still reads as
damaged, and the zero-marks check — the very control the report leans on — would
have to be run to notice. Measured cause: the corruption includes **C1 control
characters in 0x80–0x9F**, which Python's `cp1252` refuses to encode. 1,050 of the
1,081 marked lines raise `UnicodeEncodeError` on round one.

### The inverse that does work

Map characters `< 0x80` and the `0x80–0x9F` C1 range straight to their byte value,
and everything else through `cp1252`, then decode as UTF-8 and iterate:

```python
def tobytes(s):
    b = bytearray()
    for c in s:
        o = ord(c)
        if o < 0x80 or 0x80 <= o <= 0x9f:
            b.append(o)
        else:
            b.extend(c.encode('cp1252'))
    return bytes(b)
```

Verified this pass: **all 1,081 marked lines reach a fixpoint, zero marks remain.**

### Mandatory guard for whoever applies it

Run over the *whole* file, that same inverse also rewrites **389 currently-clean
lines**. It is only safe applied line-scoped — to lines that still carry a
`U+00C3` + `U+00A2–U+00AA` mark. Applying it globally would damage text it was
never meant to touch, which is precisely the failure mode this whole row exists to
prevent.

## Reusable lesson

**A fixpoint test proves only that the loop you wrote terminates — it does not
prove the loop you wrote is the right one, so a repair recipe inherited from a
report must be re-measured against the data before it is trusted with a
governance file; and when the fixpoint test fails, check whether it failed
loudly.** Here the prescribed repair threw on 97% of the lines it was supposed to
fix and the exception was swallowed into a "partial success" that would have
looked like a completed repair.
