## PART 2 - is the step-6 precondition present in the rules as written?

**Yes — on the page twice, which is why B5-0622 was an execution failure, not a
governance defect:**

- 00_BOOT step 6: *"**Absence of the claim file is NECESSARY BUT NOT
  SUFFICIENT.** Re-read the candidate row immediately before writing and
  confirm it still reads OPEN. A claim against a DONE/VOID/SUPERSEDED/BLOCKED
  row is an orphan: release it, do not work it."*
- `.agent/CLAIMS/README.md`: *"Before writing a claim, re-read the row in
  TASK_LEDGER.md and confirm it still reads OPEN... release it rather than
  work it."*

The row's fork therefore resolves to the first branch: the rule **is** in the
file, so the historical omission was the owner not executing it. That shapes
the remedy: more prose would be decoration; the rule needs to be something a
session cannot skip — but per the row, at most one improvement, proposed not
implemented.

## Reusable lesson

A rule that exists only as prose fails as prose no matter how many times it is
written — the fix is not a third restatement but putting the rule's verdict
into an instrument the workflow already runs, with an exit contract that keeps
it a report rather than a gate.

Post-write gates: run-dup-census PASS exit 0; own ledger row 7 pipes /
doubleLead no.
