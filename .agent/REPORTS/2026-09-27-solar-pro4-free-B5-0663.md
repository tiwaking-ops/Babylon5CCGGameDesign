# B5-0663 — Victory-path surfacing, engine and model leg (close-out)

## What was done

Per the B5-0663 row (gated: none; scope: `b5ccg/src/b5ccg/model/` + `b5ccg/src/b5ccg/engine/` + one VPS section in `HeadlessConformanceTest.java`), added three things:

1. **`b5ccg/model/enums/VictoryPath.java`** — enum with five values in checkVictory path order: `LAST_STANDING`, `STATION_CONDITION_2`, `AGENDA_CONDITION`, `MAJOR`, `STANDARD`. This is the canonical list of the five rulebook victory paths, matching the B5-0641 audit's measurement. A reorder would silently change which path fires when two paths qualify on the same state (30-vs-15 Major+Standard overlap — Major wins because it is tested first).

2. **`b5ccg/model/VictoryPathResult.java`** — final value object carrying:
   - `VictoryPath getPath()` — which path, or null when nobody has won (not a sentinel enum value)
   - `int getPower()` — winner's current Power (influence)
   - `Object getQualifier()` — path-specific: remaining count (Integer) for last standing, station influence (Integer) for condition 2, agenda `winConditionKey` (String) for agenda condition, lead margin (Integer) for major and standard
   - Convenience accessors `getQualifierAsInt()` and `getQualifierAsString()` for callers who know the path

3. **`RulesEngine.checkVictoryPath(GameState)`** — public query that returns a `VictoryPathResult`. Purely additive: `checkVictory(GameState)` return type (`Player`) and every caller of it (`GameController.processAction` line 136, all conformance tests, `HeadlessReportingTiebreakTest`) are untouched. The query re-derives the path in the same order `checkVictory` uses (last standing → station condition 2 → agenda condition → major → standard), so the query and the winner always agree. Returns null when `checkVictory` returns null (no winner yet).

4. **VPS conformance section** in `HeadlessConformanceTest.java` (`testVictoryPathQuery()`) — 31 checks asserting:
   - No winner → null path (two checks: fresh 2-player state, and a state where no path qualifies)
   - Last standing → `LAST_STANDING` with qualifier = remaining count (1)
   - Station condition 2 → `STATION_CONDITION_2` with qualifier = station influence (20)
   - Agenda condition (MILITARY_SUPREMACY met at 15 power) → `AGENDA_CONDITION` with qualifier = `"MILITARY_SUPREMACY"`
   - Major victory (30 vs 15) → `MAJOR` with qualifier = lead margin (15); major-over-standard precedence asserted (not `STANDARD`)
   - Shadow War suppresses standard condition 1 → null path (20 vs 15, lead 5 < 10, Shadow War blocks standard)
   - Shadow War admits major (30 vs 15 during Shadow War) → `MAJOR` with qualifier = 15
   - Standard victory (25 vs 20, lead 5 < 10 so no major) → `STANDARD` with qualifier = 5
   - 30-vs-15 overlap → `MAJOR`, not `STANDARD` (path-order precedence)

## Verification detail

The VPS section exercises each path through the real `RulesEngine` API. For station condition 2, it uses the same pattern as the VIC section: `state.getStation().gainInfluence(20)` to raise station influence to the 20 threshold, with exactly one standard-eligible player strictly leading. For the agenda-condition path, it constructs a `MILITARY_SUPREMACY` agenda directly (the existing `agendaCard()` helper only makes `INFLUENCE_20`) and adds a fleet to satisfy the "most Military" condition. For Shadow War, it uses `station.setShadowInfluence(CONDITION_2_THRESHOLD)` — the same pattern as the MJR section — which triggers the Shadow War guard in both `stationVictory` and `standardVictory`.

## Reusable lesson

A victory-check method that returns Player-only is a silent abstraction leak — every downstream consumer that wants to know WHY the game ended (UI, log, AI post-mortem, reporting tiebreak) must re-derive the path from the same state the engine already evaluated, which invites divergence between the engine's actual path and the consumer's reconstructed path. The fix is additive (a query that returns the path + qualifier) rather than changing the existing return type, which keeps every existing caller working and lets the UI leg (B5-0665) consume the new API without touching engine internals.
