## The headline: the row's own premise was wrong, and so was the control

The row asserted the 7 hits were false positives because "the literal
substrings `registry-open-parenthesis`, `entry-open-parenthesis` and
`country-open-parenthesis` match it inside prose". **They do not.** Measured:


## Triage of the other two classes (recorded, NOT fixed)

Per the row: fix neither, but record whether each is a genuine finding or a
detector defect.

**A. "Main.java has 160 unexpected diff lines vs archive" - DETECTOR DEFECT,
and a large one.** `verify_task.py:120-126` compares line *i* to line *i*
positionally rather than diffing:

```
live lines=188 archive lines=162
POSITIONAL differing lines=172  unexpected(accidental)=160
TRUE diff (SequenceMatcher) insert/replace=16 delete/replace=16 total=32
opcode summary: {'equal': 10, 'insert': 2, 'delete': 0, 'replace': 7}
CONTROL single-line insert -> positional unexpected=151  true diff lines=1
```

One inserted line yields **151** "unexpected" lines under the positional
comparison and **1** real diff line. The 160 is an artefact of a ~19-line
insertion shifting every subsequent line by one index; the sample output makes
this plain (`try {` compared against `@Override public void run() {`). The true
edit distance is **32**. So: the finding is *directionally* real - Main.java
genuinely differs from the archive - but the number 160 is meaningless and must
not be quoted as a measure of divergence. The `intentional_markers` allowlist
cannot repair this, because a shifted line matches no marker.

**B. "168 .md files missing author_llm provenance" - GENUINE FINDING.** The
detector discriminates correctly, established with a positive and a negative
control before believing the number:

```
md scanned=1245  present=1077  missing=168
CONTROL positive 00_BOOT.md     -> has_provenance=True  (expect True)
CONTROL negative loop-prompt.md -> has_provenance=False (expect False)
missing by namespace: [('.agent/REPORTS', 136), ('.agent/PATTERNS', 30), ('docs/proposals', 2)]
```

Not a detector defect, and **heavily namespace-concentrated**: 166 of 168 (99%)
sit in `.agent/REPORTS` and `.agent/PATTERNS` - agent-authored close-out
artifacts - against 2 in `docs/proposals`. That is a different problem from a
scattered 168, and it is exactly what B5-0839 was seeded to measure. I changed
no `.md` file and fixed no provenance, per the row: mass-adding an `author_llm`
line to a file whose true author is unknown would fabricate the record AGENTS.md
section 1 forbids inventing.
