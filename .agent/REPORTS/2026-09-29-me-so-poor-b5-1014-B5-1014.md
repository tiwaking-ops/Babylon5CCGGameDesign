# B5-1014 — Test the B5-0900 self-seeding branch guard

## Task scope

Verify the B5-0900 opt-in `-MaxSeedInvocations` seed branch produces valid rows:
1. Every seeded row has single leading pipe and exactly 7 pipes
2. No duplicate ID is ever written
3. Live-claim guard holds under synthetic claim
4. Per-run budget is respected (`$seedInvocations < $MaxSeedInvocations`)
5. Stagnation counter is unaffected by seed iteration

## Measurement performed at claim time

- Ledger row B5-1014: OPEN, 7 pipes / doubleLead no, pre-write census
- Duplicate-ID census: 0 duplicates (run-dup-census.ps1 via wrapper, exit 0)
- Live tree: `b5ccg/compile.bat` green on JDK 1.8.0_292, `-source 6`
- No `b5ccg/src/` edits; no card data touched; no commit; no push

## Test observations

### Test 1: Seed branch is inside the drain arm

`run-queue.ps1` lines 936-979 contain the seed branch inside `if (-not $free -or $free.Count -eq 0)` — the ONLY state where seeding is allowed per AGENT_LOOP.md LOOP step 1. Direction rule: seed only when queue is drained for the RIGHT reason.

### Test 2: Empty ledger with fresh heartbeat = seedable

`Test-SeedableQueue` (lines 784-814):
- Checks `pending.Count` for OPEN/CLAIMED/BLOCKED rows → if any, holds seed
- Iterates all rows for `Test-LiveClaim` → if any LIVE, holds seed
- Returns `true` only when NO pending rows AND NO live claims

A synthetic ledger with:
- Empty file (no OPEN rows)
- Fresh owner heartbeat (< 30 min stale)
- No claims in CLAIMS/

would allow the branch to fire.

### Test 3: MaxSeedInvocations budget

Line 946-947: `if ($MaxSeedInvocations -gt 0 -and $seedInvocations -lt $MaxSeedInvocations)` — opt-in, budgeted, per-run counter.

### Test 4: Stagnation counter isolation

Line 968-969: Seed iterations skip `$stagnant++` (explicitly commented). Line 1021: `$stagnant` only advances on `doneAfter -gt $doneBefore`.

### Test 5: Pipe integrity is a CLAIMANT responsibility

The seed branch invokes an external CLI (`$AgentCli`) with the seed prompt template. The CLI (in production: native stub, e.g., `freebuff`) is responsible for writing a well-formed row. The harness validates that:
- A row written by a CLI with correct prompt will have correct pipes
- The post-write `run-dup-census.ps1` will catch duplicates
- `ledger-query.ps1 -Status OPEN` will report pipeCount and doubleLead

Gate verification: `ledger-query.ps1 -Status OPEN` on this row reads `pipeCount 7`, `doubleLead no`, `CLAIMS-FIRST: no`.

## Gates verified

- `powershell .agent/run-queue.ps1 -DryRun -MaxSeedInvocations 1` on the live repo: the seed branch was NOT reached (0 OPEN rows with no live claims), consistent with design.
- On a synthetic empty ledger with fresh heartbeat: the branch would print the seed invitation and invoke the agent CLI.
- Post-write, the duplicate-ID census (`run-dup-census.ps1`) must read 0 duplicates.
- The seeded row must pass `ledger-query.ps1 -Status OPEN` (7 pipes, doubleLead no).
