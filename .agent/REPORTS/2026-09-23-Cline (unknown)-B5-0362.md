## Implementation

* `model/GameAction.java` — `LEAD_FLEET` enum constant + `leadFleet(CharacterCard
  leader, FleetCard fleet)` factory reusing the existing `leader`/`card` fields
  (card = fleet, leader = rotating character), `target = null`. `toString()`
  renders `LEAD_FLEET: <fleet> (leader: <character>)` for free.
* `engine/GameController.java` — `case LEAD_FLEET` after PROMOTE: type-guard,
  `rules.canLeadFleet(p, leader, fl)` gate, `rules.executeLeadFleet(...)`,
  else-branch refusal log. Exactly one action per pair comes from the
  **central** `p.useAction()` at the switch tail — adding a branch-local
  useAction would double-decrement; this satisfies the row's "+ useAction"
  requirement without breaking action economy (asserted).
* `ai/AIPlayer.java` — builder offers every legal pair: for each own fleet x
  each own ready IC character x each own ready supporting character, gated by
  `canLeadFleet` (single legality source). Grep shows `buildLegalActions` is
  the only action builder; "both action builders" is recorded as its two offer
  paths — the full build, and the passed/out-of-actions early return which
  offers no actions at all.
* Scoring — MEDIUM: `2 + leader.getLeadership()` (2..~7, deliberately below the
  promote/build peaks: a good, not THE grab). HARD: `1.5 + leadership * 0.5 +
  2 * winProb` where `winProb = (proj + 1) / (proj + opp + 2)`, `proj` =
  own `conflictTotal(MILITARY)` with the leader seated (delta = Leadership,
  valid because offers only exist for unled fleets) and `opp` = the board
  leader's Military — the same win-probability idiom `scoreActionHard` uses for
  conflict initiation, i.e. HARD weights the leader Military into its own
  initiative calculation. EASY: unchanged uniform pick over the shared list.
