# B5-1017 - Reconciling the two liveness divergence records

## The exact code path, named

`.agent/tools/ledger-query.ps1` claim indexing (Get-Content/ConvertFrom-Json
with mtime fallback): `started_utc` is `[DateTime]::Parse`d — a **forged-future
value parses fine** — and is then folded into the three-signal newest
arithmetic. The verdict line `if ($newestMin -lt $TtlMinutes) { "LIVE" }`
computes `now - started` as a **negative age**, and a negative number is less
than any positive TTL → **LIVE**. That is the B5-0609 inversion (absent/wrong
signal read as fresh) reached through a *fresh but false* signal — the B5-0952
forged class. The B5-0998 measurement (−554.4 min printed as LIVE on B5-0953)
is exactly this line. `.agent/run-queue.ps1` Test-LiveClaim instead returns
UNSTEALABLE on `started -gt $now` (line ~620: `if ($started -gt $now) { return
$true }` — not-offered with a future-dated claim) and on missing-heartbeat
UNKNOWN (B5-0953 fix, returns unstealable) — so the runner **declined to offer
the same claim the query printed LIVE**.

## What a negative age does to a consumer

Any consumer reading the age column directly compares it against the TTL:
negative < 30 → fresh → LIVE. A consumer checking `age < 0` as a
sanity guard would catch the forgery, but the shipped consumer (the printed
verdict) does not — it compares the raw age. A forged-future timestamp is
therefore **maximally fresh** to every arithmetic consumer, which inverts the
safety direction: the more brazen the forgery, the more live the claim reads.

## The design choice, stated per the row

**The two designs are each defensible and were kept deliberately different —
what was missing was the label.** A query tool should report what the files say
(the age −554.4 is a *fact about the file*; hiding it would destroy the evidence
a human needs to adjudicate the forgery). A runner should apply policy (never
offer on an unverifiable signal). B5-0775's precedent is that a replica must
mirror the original's *rule*; the complementary rule is that a **reporter must
not silently adjudicate**, and a **policy tool must not silently report**. The
defect was never that the tools differ — it is that nothing on the page said
which mode a reader was looking at.

## The implementation

In `.agent/tools/ledger-query.ps1`, verdict cells for claims whose
`started_utc` was accepted from the file (parseable, non-null) now carry an
explicit reason label; the arithmetic is untouched:

- plausible past timestamp → `LIVE [reported-age:started_utc-unverified]` /
  `STALE [reported-age:started_utc-unverified]`
- future-dated timestamp → `LIVE [reported-age:started_utc-is-future-dated]`
  (negative age still printed in the age column — reported, not hidden)
- UNPARSEABLE claim → `UNKNOWN [claim file present but unparseable...]`
  (unchanged)
- absent heartbeat → `UNKNOWN [no heartbeat file matching owner ...]`
  (unchanged — never LIVE, per B5-0659)

Compatibility: `census-crosscheck.ps1` compares via `Get-Word`, which reads the
leading token — labels ride after it, so no crosscheck change is needed (and by
B5-0775's own lesson the crosscheck replicates rules rather than invoking this
tool, so there is no replica to update).

## Reusable lesson

Two tools with a defensible disagreement need a label naming which one you are
reading, not a forced convergence — a reporter must not silently adjudicate and
a policy tool must not silently report, and the proof that the difference is
now explicit is a fixture where the forgery prints its own name on the verdict.
