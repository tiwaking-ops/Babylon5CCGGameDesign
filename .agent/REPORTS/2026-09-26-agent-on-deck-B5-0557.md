(rulebook victory)" — meaning the game did NOT reach a victory condition
within the probe's 3-round window.

**Reproduced on committed HEAD (b5eabc89)**: ran `git stash` to revert all
working-tree changes, compiled against committed code, and ran the same
probe — it produced the identical 1/37 failure. This confirms the 0443
failure is **pre-existing and unrelated** to the B5-0556 MINES reactive-
damage fix or any other change in this session.

game for 3 rounds max (30s window) and expects a victory condition. Games
that don't reach a winner in 3 rounds fail this check — a known harness
timeout behavior (documented in B5-0349/B5-0409 notes about the 60s per-game
window and quiet pass-heavy rounds).

is a 30-second insurance policy against false regression attribution. The

that don't reach a winner fail, which is a harness timeout characteristic
not an engine regression (see B5-0349/B5-0409 for the same pattern on the
60s window).
