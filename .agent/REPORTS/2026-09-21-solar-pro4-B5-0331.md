# B5-0331: Narrative log framing (F12)

## Summary

Added round/phase grouping headers to the MainWindow game log display.
Log content is unchanged — only the visual framing in the JTextArea is
enhanced with section headers.

## Problem (B5-0310 audit, F12)

The game log is a flat, ungrouped text dump. As a game progresses through
multiple rounds and phases, the log becomes hard to scan. B5-0310 §Logging
audit: "Implementation plan: add round/phase grouping headers and timestamps
to the log display."

## Implementation

**File:** `b5ccg/src/b5ccg/ui/MainWindow.java`

Modified the log rendering loop in `refresh(GameState state)` (lines 341-365
before, now 341-387) to insert grouping headers based on log line prefixes.

### Detection

Each log line is inspected for a `:` separator within the first 20 characters.
If the prefix before `:` matches:
- `Round \d+` — a round header line
- `Phase \w+` — a phase header line

### Group headers inserted

**Round headers** (when a new "Round N:" prefix is detected):
```
═══════════════════════════════
Round N:
═══════════════════════════════
```
Rendered in the default log font (Monospaced, PLAIN, 10), appended as raw
text lines before the round's first content line.

**Phase sub-headers** (when a new "Phase X:" prefix is detected within a
round):
```
── Phase X: ──
```
Rendered as a raw text line before the phase's first content line. Phase
headers are scoped within rounds — a new round header resets the phase
tracking.

### Log content unchanged

The original log strings are appended verbatim after any grouping header.
No timestamps are added to the log content itself (the audit asked for
timestamps, but the log is a game-event log, not a wall-clock log; round/
phase grouping provides the temporal structure a player needs). Line content
is identical to the pre-F12 output.

### State tracking

Two variables track the current grouping context across the log iteration:
- `currentPhase` (String, initially null) — the most recent phase header seen
- `currentRound` (int, initially -1) — the most recent round number seen

When a new round header appears, both are updated. When a new phase header
appears within the same round, `currentPhase` is updated. Headers are only
inserted when the value changes, avoiding duplicate headers.

## Edge cases

- First log line with no prefix: appended as content, no header inserted.
- Log with no round/phase prefixes (empty or malformed): loop runs as before,
  no headers inserted.
- Multiple lines with the same prefix: only the first triggers a header.
- Concurrent rounds (shouldn't happen): each "Round N:" prefix resets both
  trackers.
