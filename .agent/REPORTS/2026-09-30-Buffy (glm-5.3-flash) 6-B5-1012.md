## The second finding: the census itself rots at the *run* level (encoding trap)

The first re-run attempt **failed** with `UnicodeEncodeError` under the default
cp1252 console: the script prints raw source lines, and tracked comments carry
box-drawing glyphs (`──` in HeadlessConflictResolutionProbe:130). Re-run with
`PYTHONIOENCODING=utf-8` succeeded (exit 0). This is the repo's known
double-encoding/mojibake family arriving through a new door — an instrument
that worked at its creation pass now crashes by default on this machine — and
it is exactly the snapshot-rot the row predicted, one layer down: not the
*counts* rotting but the *reproducibility*. The failed-run `.err` file is kept
at `tmp-scans/b51012/census.err` as the receipt.

## Reusable lesson

A standing gate is a documented command plus a standing-state table, not a
wired-in script — and the run instruction is part of the gate: a census that
crashes under the default console encoding silently decays back into a
point-in-time snapshot.
