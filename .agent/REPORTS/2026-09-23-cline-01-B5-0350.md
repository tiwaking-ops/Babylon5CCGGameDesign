# B5-0350 — Option C reporting tiebreak (harness / report layer)

## Task

NEW harness/report-layer file only: when a round cap is hit with 2+ players at
20+ influence and no winner, report the deterministic chain (fleet Military →
Inner Circle size → influence gained → shared victory). The engine's
`checkVictory` stays rulebook-pure. No game-logic edits.
Design source: `docs/proposals/tiebreak-agenda-victory-design-proposal.md` §2
Option C + §4 verification hooks.

## Deliverable

* `b5ccg/src/b5ccg/engine/HeadlessReportingTiebreakTest.java` — the ONLY file
  added or changed by this task (617 lines, Java 6, stdlib only).
* Public report layer: `evaluateAtRoundCap(GameState, RulesEngine, int[])` →
  immutable `TiebreakReport` (`Kind` = ENGINE_WINNER / NOT_APPLICABLE / SINGLE /
  SHARED; `step`; unmodifiable `winners`; human-readable `detail`;
  `isWellFormed()`).
* Behavior:
  1. Engine first — `state.getWinner()` / `checkVictory()` short-circuits to
     ENGINE_WINNER (strict standard lead, agenda win, station condition 2, last
     standing). Reporter applies nothing over a rulebook winner.
  2. Trigger — ≥2 non-forfeited players at ≥20 influence with no engine winner;
     fewer → NOT_APPLICABLE (report says why: N of M at 20+).
  3. Chain, each step narrows to the max-tied subset:
     step 1 `Player.conflictTotal(MILITARY)` → step 2 `getInnerCircle().size()`
     → step 3 `getInfluence() − baseline` (baseline parallel to
     `state.getPlayers()`, captured at run start) → step 4 declared SHARED
     victory among the remaining ties.
* Interpretation recorded: "committed fleet Military" (proposal wording) is read
  as `conflictTotal(MILITARY)` — ready fleets at effective value incl. seated
  leader, rotated fleets 0 (B5-0337/D5). No cross-round committed-card registry
  exists in the engine (conflicts resolve within a round), so no other reading
  is computable inside a new-file-only scope.

## Notes / limitations

* The live phase's *kind* is not asserted (it depends on play; a fresh run is
  always NOT_APPLICABLE at the round-1 boundary). Well-formedness and
  capture-at-boundary are asserted.
* Forfeited players are excluded from contenders; a forfeit that leaves one
  standing is an engine decision anyway (last-standing path), so that branch
  routes to ENGINE_WINNER before the gate.
* `startInfluence` must be parallel to `state.getPlayers()` — mismatch throws
  `IllegalArgumentException` (loud, per house style).
* No conformance-suite or `compile.sh` edits (harness rows never touch
  `HeadlessConformanceTest.java`); the harness is standalone CLI like
  `HeadlessMultiRoundTest` / `HeadlessAIDifficultyContractTest`.
