# B5-0988 close-out — the B5-0974 recommendation, actioned

## Change

One new file, `.gitattributes` at the repo root, carrying exactly one rule:

```
b5ccg/compile.sh text eol=lf
```

plus a comment citing B5-0974 and the B5-0306 precedent (a CRLF shebang breaks
stricter `sh` builds; this repo's Git Bash tolerated it, which is why the warning
was cosmetic until someone ran the script under a stricter interpreter).

The warning is the `LF will be replaced by CRLF the next time Git touches it`
class: with `core.autocrlf=true` and no attributes, any future checkout/rebase
would rewrite the script to CRLF on disk, which Git Bash tolerates and stricter
`sh` builds do not. The `eol=lf` attribute pins the script's on-disk form at
LF permanently, which retires the warning *and* the underlying hazard, not just
the message.

## Reusable lesson

A conversion warning names the moment of next damage, not the damage itself:
retiring the message without pinning the attribute would leave the CRLF rewrite
armed and silent. The fix is one scoped attribute line plus four probes — rule
applies, warning gone, artifact still valid, no collateral — and the negative
control (the rule must not leak to files that want the platform default) is what
makes "scoped" a measurement instead of an intention.
