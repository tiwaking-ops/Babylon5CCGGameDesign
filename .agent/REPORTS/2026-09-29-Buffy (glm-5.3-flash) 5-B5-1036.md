# B5-1036 - The ENHANCEMENT cost-free class, traced to a behaviour

Read-only: no JSON edited, no src edited, no commit. Instruments named: python3
json.load over both card files, line-level reads of
[DeckLoader.java](b5ccg/src/b5ccg/engine/DeckLoader.java),
[RulesEngine.java](b5ccg/src/b5ccg/engine/RulesEngine.java),
[GameController.java](b5ccg/src/b5ccg/engine/GameController.java),
[CardEffects.java](b5ccg/src/b5ccg/engine/CardEffects.java).

## The class, re-measured

Exactly one ENHANCEMENT per file carries the five Bonus fields with no `cost`
key: `enh_judgment_by_success` (premiere, 41 enhancements) and
`de_enh_judgment_by_success` (deluxe, 37) — the census of record confirmed.
Both records: subtype `ENHANCEMENT_FACTION`, **all five bonus fields = 0**,
identical text: "Faction Enhancement. Gain 1 Influence whenever you win two or
more conflicts in the same round."

## The trace: what the loader and the attach path actually do

1. **Loader** ([DeckLoader.java:93-101](b5ccg/src/b5ccg/engine/DeckLoader.java#L93-L101),
   B5-0323): an absent or empty `cost` key is **not an error** — the card parses
   with cost defaulting to 0 (negatives clamp). **No crash at load.**
2. **Attach legality** ([RulesEngine.java:904-907](b5ccg/src/b5ccg/engine/RulesEngine.java#L904-L907)):
   `canPlayCard(p, c)` = hand membership + `faction.isPlayableBy`. **It never
   reads cost.** Enhancements reach the engine via `PLAY_CARD`, not via the
   character sponsor path.
3. **The play path** ([GameController.java:629ff](b5ccg/src/b5ccg/engine/GameController.java#L629),
   `applyGenericCardPlay`): removes from hand, logs, dispatches by type — and
   **charges no influence for ANY card type**. The sponsor-cost machinery
   (`baseRecruitCost`/`sponsorCost`, B5-0323/B5-0339) is wired only into
   `RECRUIT_CHARACTER` and `PROMOTE_CHARACTER` (CharacterCard-only branches).
   Enhancements, Groups, Locations, Events and Agendas all play for free today,
   **costed or not**.
4. **The effect** ([CardEffects.java:221ff](b5ccg/src/b5ccg/engine/CardEffects.java#L221),
   `applyPlayEnhancement`): subtype branch → faction branch → applies the five
   bonus deltas (all 0 → a mechanical no-op) and adds the card to
   `p.getEnhancements()`. The text's win-2-conflicts trigger is **prose only** —
   `CardEffects` has no `judgment` entry (grep empty), so nothing grants the
   Influence.

## Verdict: SAFE — no crash, no exploit specific to this record, and the missing cost is currently indistinguishable from a present one

| Hypothesis | Verdict | Evidence |
|---|---|---|
| Crash | **No** | Absent key → default 0 at the one read site; no other code touches an enhancement's cost. |
| Exploitable (free-card) | **Not distinctively** | Cost is never charged on the PLAY_CARD path **for any type** — the 72 costed enhancements play free too. A player drawing judgment_by_success gains nothing a costed sibling doesn't already give for free. The free-play class-wide gap is pre-existing, known (B5-0323 scoped cost to recruit/promote), and not this record's defect. |
| Unattachable | **No** | `canPlayCard` passes; attach succeeds (as a 0-delta no-op attachment). |
| Free to attach | **Yes — but vacuously** | It attaches for free like everything else; with all bonuses 0 and the trigger undispatched, the card is mechanically **inert cargo**: it occupies a hand slot and a enhancements-list slot and does nothing. |
| Attachable by an unstated rule | N/A | No rule text exists to state it. |

So the B5-0996 "Class D, cost genuinely absent" classification now ends in a
behaviour, as this row required: **safe, well-defined by accident (absent → 0 →
free, uniform with the whole dataset), and behaviourally invisible.**

## The single smallest change that makes the class well-defined, and the one seeded row

The hole is not the two records — it is that **cost is unread cargo on the
entire PLAY_CARD path**, so no enhancement's cost (0 or not) means anything
mechanically. The smallest change with real teeth: a **cost gate on the generic
play path** — in `applyGenericCardPlay`, charge `card.getCost()` influence (with
the same affordance refusal + log pattern the RECRUIT branch already uses, and
`canPlayCard` extended with the affordability precheck). That one site makes the
whole enhancement class well-defined: cost-free = free to attach (a now-meaningful
statement), costed = costs influence. **Seeded as B5-1038** (the one permitted
follow-up), with the explicit note that the two judgment_by_success records then
need a human-supplied printed cost — no in-repo source states one, and inventing
a value is a balance decision the data alone cannot make. No change was made in
this row, per scope.

## Reusable lesson

A "missing field" question resolved to "the field is unread cargo on this whole
code path" — before adjudicating a record as a schema hole, trace every consumer
of the field: when the *present* values are consumed nowhere either, the record
is not the defect, the dead path is, and the smallest well-defined fix moves
from data (backfill 2 records) to model (one gate at the read site).
