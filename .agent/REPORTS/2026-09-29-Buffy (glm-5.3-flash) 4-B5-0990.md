## The rule interpretation the code encodes

Resolution (`RulesEngine.resolveConflict`) rotates **every committed fleet**.
So "the loser may keep one fleet from being rotated" is implemented as
**restoring one rotated fleet the loser committed** (first in committed order;
logged no-op when the loser committed no fleet). The "Gain 1 Influence" (and
the Deluxe "loser also draws 1 card") belong to the **loser**, so the effect
fires on the played-upon target only when that target actually lost
(`target != winner`) — **never on a won one** (rulebook Won/Lost conditions,
audit D1). Play legality stays with `RulesEngine.canPlayAftermath`, unchanged.

## Reusable lesson

**An effect that looks like a state change ("keep one fleet from being
rotated") is a guard against the engine's own prior action, so implement it as
an inverse of that action and pin it with a setup-first check.** Resolution
rotates committed fleets; the effect restores one — and the conformance check
that asserts the precondition (`fleet.isRotated()` before, ready after) is what
makes the interpretation falsifiable rather than decorative.
