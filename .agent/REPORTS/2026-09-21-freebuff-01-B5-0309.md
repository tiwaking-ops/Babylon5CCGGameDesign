# B5-0309 — Conflict support/opposition sides (rulebook win rule)

Agent: `freebuff-01`. Toolchain: `javac 1.8.0_292` (`-source 6 -target 6` gate).

## Rule

Rulebook, section **Conflicts** (BABYLON5_CCG_RULEBOOK.md line 546):
*"If a conflict receives more support than opposition, then the faction which
initiated it 'wins' the conflict. If a conflict receives the same amount or
more opposition than support, then the faction which initiated it 'loses'."*

Pre-fix (audit deviation **D14**, report-only): `Conflict.commitCard` recorded
cards but no side; the engine's `resolveConflict` faked the rule with a
*highest-total-wins* heuristic — which crowned the **initiator on a tie**
(the initiator's own total broke the strict-`>` scan as the baseline) and
let any high-total participant steal a conflict they were "supporting".
The rulebook outcome is a property of **sides**, not of the best individual.

## Changes (4 files)

1. **`model/Conflict.java`** — per-participant side sets (`supporters`,
   `opposers`, LinkedHashSet, identity semantics); the initiator supports his
   own conflict by construction. New `commitCard(p, c, boolean)` /
   `addParticipant(p, boolean)`; the legacy one-arg overloads default to the
   **support** side, so every existing caller (UI, smoke test, D1/D3 suite
   sections) keeps its meaning. New `supportTotal()` / `oppositionTotal()` /
   `isSupporting(p)` / `isOpposing(p)`; `playerTotal` now delegates to the
   shared per-player sum.
2. **`engine/RulesEngine.resolveConflict`** — the rulebook rule: initiator
   wins iff `supportTotal() > oppositionTotal()` **or** opposition is 0
   (unopposed conflicts are auto-wins; degenerate all-zero board included);
   otherwise the **leading opposer** (highest total, insertion order breaks
   ties) wins. Log line now reports both side totals. Loser-penalty wiring
   (CardEffects, fleet rotation, supporting-role discards) unchanged — it is
   side-agnostic and keyed on "not the winner".
3. **`engine/GameController`** — AI join path commits joiners and their
   ambassadors to the **opposition** (`false`); the initiator's ambassador
   commit is explicit `true`. This is the smallest faithful join semantic;
   deliberate oppose-as-strategy is future AI work.
4. **`engine/HeadlessConformanceTest`** — new **CSD** section, 8 checks.

Also noted in-code (not a behavior change): the ambassador-damage rule fired
for **any** conflict type on a ≥3-point loss; damage is a MILITARY-resolution
consequence, so the check is now type-scoped (audit **D10** note recorded).

## Conformance suite (CSD ×8; 37 → 45 checks total)

- Side recording + totals for the initiator's own conflict
- support 3 vs opposition 0 → initiator wins (engine path)
- support 3 vs opposition 3 → initiator **loses**, opposer wins — the exact
  pre-B5-0309 bug (tie crowned the initiator)
- Tie loss damages nobody (gap < 3)
- support 3 vs opposition 5 → leading opposer wins
- support 3 vs opposition 8 → loser's ambassador damaged (`damage()` =
  face-down); a face-down character contributes 0
- Legacy overloads default to the support side

Two earlier draft checks (a Leadership-mirror via a test hook) were removed
by design: D5's one-character-leads-one-fleet relation needs a model relation
the audit explicitly deferred to a future task, and a mirror-based check
would have tested the harness more than the product.
