## Recommendation (ordered sequence for human-approved removal)

**Phase 1 — Untrack (safe, reversible, no history rewrite):**

1. `git rm --cached node_modules/` — removes 67,258 files from the index; working tree keeps them. One commit.
2. `git rm --cached conformance-original.txt conformance-post-pop.txt` — removes the two stale conformance snapshots.
3. `git rm --cached java` — removes the 0-byte litter file.
4. Add `node_modules/` to `.gitignore` — prevents re-entry.
5. Leave `src/`, `package.json`, `dist/`, `README.md` — the human decides whether these stay.

**Phase 2 — History rewrite (destructive, separate decision):**

If the human decides the Figma scaffold (`src/`, `package.json`, `dist/`, `README.md` modifications) should never have been in the repo, an interactive rebase (`git rebase -i d1d0c6ff^`) could remove those paths from commit `d1d0c6ff`. This is **not** recommended without explicit human approval — it rewrites every subsequent commit hash and invalidates all checkpoint commits.

**Phase 1 is the default recommendation.** It removes 98.7% of tracked file count and ~192 MB from the index with a single reversible commit, leaves the Java engine untouched, and preserves the option to delete the scaffold later.

## Reusable lesson

A repository's tracked-file count is dominated by its largest ignored-style directory (here `node_modules/` at 98.7%), and the entry commit for that directory is often NOT the scaffold import commit — `npm install` output is committed separately, so `git log --diff-filter=A -- node_modules/` is the accurate citation, not the Figma import commit.
