## Design notes

- The UI does not decide Censure-class membership — the engine owns that via `GameAction.hasExplicitTarget()` and the printed FLEET subtype. The control is a read-only picker forwarding a user choice through the existing seam, so a future card-text-driven Censure concept would not require a UI change.
- Follows the existing B5-0407 declare-war selector pattern: `JComboBox` + label + `refresh` method + button + guard.
- Empty opponent pool renders "(no opponent fleets available)" — never shows an empty dropdown as if it has items.
- The censure play button is the ONLY path for targeted Enhancement FLEET plays; the generic Play Card button cannot bypass the explicit target (enforced in `playOnly()`).

## Reusable lesson

**Seam-first UI disables until ready.** When a UI control depends on an engine seam whose eligibility is resolved externally (here, Censure-class via `hasExplicitTarget()`), build the control to a known disabled/empty state and only populate/enable it from a refresh method that re-derives eligibility from live state — never cache eligibility at init time. This keeps the UI correct across state transitions (card change, phase change, player change) without duplicating engine logic.
