## Triage findings

### 1. No near-class wiring detour exists in HeadlessConformanceTest.java

`HeadlessConformanceTest.java` is NOT a wiring file — it is a pure test
harness (extends nothing relevant, only `main()` + test methods). There is NO
Censure-edition logic, no ENHANCE/FLEET bonus-application logic, no
target-resolution logic, and no stat-modifier logic anywhere in that file
beyond the test scaffolding that exercises the real engine. Any future
CHARACTER-host extension of the B5-0473 opponent-targeted path would land in
`CardEffects.applyPlayEnhancement` (or a sibling engine method it delegates
to) and would be covered by adding test cases to
`testOpponentEnhancementWiring()` or a sibling suite method — NOT by editing
`HeadlessConformanceTest.java`'s test-harness infrastructure.

Concrete evidence: the ENH-WIRE cases in that file (`enh_censure_w1`,
`enh_legacy_w1`, `enh_ghost_w1`, `enh_pipe_w1`, and the non-wire
`enh_seam_1`, `enh_legacy`) are test-case DATA (card type + printed text +
expected outcome), not wiring logic. The harness feeds them into the real
engine and asserts outcomes. There is no bonus-calculation branch, no
StatKey/MILITARY clamp, no registry grant path, and no target-lookup path
anywhere in the harness that could be "detoured" by a future CHARACTER host.

### 2. No CHARACTER-host enhancement skeleton exists in CardEffects.java

Reading `CardEffects.java` (the actual wiring home) confirms there is no
`_CHARACTER` branch in `applyPlayEnhancement`, no character-target
resolution path, and no stat-bonus grant path onto a character card. The
method's enhancement-application surface is currently fleet-only. This is
consistent with B5-0494's own finding (the future CHARACTER-host extension is
anticipated but NOT yet wired) and with B5-0473's delivery (fleet-only
opponent-targeted path).

### 3. The Censure card data already carries what a future CHARACTER host
would need

The B5-0468 seam (`targetOwnerName`, `targetCardIndex`, `hasExplicitTarget()`,
accessors) is character-host-agnostic: it names a target PLAYER and a target
FLEET index. A future CHARACTER-host wiring would need either (a) a new target
card-id field for characters, or (b) a different resolution convention for
character targets — neither exists yet, and neither is implied by the current
seam. B5-0494's own report recorded this as an anticipated gap. B5-0497
confirms the gap is still open and that no partial CHARACTER wiring is hiding
in either file.

### 4. The B5-0473 row's delivery cell is accurate

The ledger row text for B5-0473 says the delivery is
"b5ccg/src/b5ccg/engine/ plus its HeadlessConformanceTest section only." This
is correct: CardEffects.java (engine/) held the wire, and
HeadlessConformanceTest.java (also engine/) held the suite extension. The row
does NOT claim a separate seam file for 0473 — that is correct because the seam
(B5-0468) was a predecessor task and 0473 consumed it. Any reader looking for
the actual Censure-wiring code should open `CardEffects.java`, not
`HeadlessConformanceTest.java`. This triage records that fact explicitly so a
future worker does not open the wrong file.

### 5. No OTHER near-class detour candidate exists in engine/

No other file in `b5ccg/src/b5ccg/engine/` is a detour candidate for a future
near-class enhancement wiring:

* `HeadlessConformanceTest.java` — test harness only (above).
* No other `CardEffects`-adjacent file carries enhancement-application logic.
* The model package (`model/`) holds card data and state; the B5-0468 seam
  already lives there and is the data side. No new model class is implied by
  the current task set.

## Verdict

There is NOTHING waiting to be wired in the near-class enhancement path right
now. The B5-0473 opponent-targeted fleet path is landed and green. The future
CHARACTER-host extension that B5-0494 anticipated does not exist in code yet,
and the test harness (`HeadlessConformanceTest.java`) is the wrong place to
look for it — the wiring would land in `CardEffects.java` and the test cases
would extend `testOpponentEnhancementWiring()` or a sibling method. No task is
created by this triage; the verdict is "nothing here, move on."
