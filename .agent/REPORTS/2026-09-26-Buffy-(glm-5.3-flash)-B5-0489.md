## Finding F1 (NEW defect, hand-off to fix slice — not fixed here, execution-only scope)

`HeadlessLeadFleetScenarioProbe` crashes deterministically (3/3 runs, identical trace) with:

```
Caused by: java.lang.NullPointerException
    at b5ccg.model.FleetCard.getEffectiveMilitary(FleetCard.java:59)
    at b5ccg.engine.RulesEngine.executeLeadFleet(RulesEngine.java:878)
    at b5ccg.engine.GameController.processAction(GameController.java:272)
```

Root cause (file-and-line evidence): B5-0486's floor pass inside `FleetCard.getEffectiveMilitary()` (FleetCard.java:57-64) iterates `owner.getBonuses()` without re-guarding `owner != null` — line 59 `for (StatBonus b : owner.getBonuses())` sits *outside* the `if (owner != null)` block that protects the `owner.effectiveStat(...)` call on line 55. The pre-floor method was null-safe; the floor edit introduced the NPE. The probe's fixture fleet has no owner, so the defect was invisible to the conformance suite (its fixtures all set owners) and smoke. This is exactly the class of regression this row exists to catch: **the floor pass sits in a scoring-read path, and a green suite alone does not cover it** (the row's own rationale).

Notably, B5-0476 (the previous re-sweep) ran this probe green at 8/0 — the crash postdates it, and the only military-read-path change since is 0486's floor pass.

**Hand-off:** fix slice self-seeded as B5-0494 (`b5ccg/src/b5ccg/model/` + one probe fixture line, smallest diff: hoist the floor loop inside the existing `if (owner != null)` guard; also audit `getGreatestAbility` same-file null-safety). Per protocol I did not fix it under this execution-only claim.
