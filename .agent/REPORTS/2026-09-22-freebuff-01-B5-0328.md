## Defects found in the committed draft (91bc1b7)

1. **Selection leak:** the hand-selection listener ended with an unconditional
   `playCardOnlyButton.setEnabled(true)` — "Play Card" lit for a *conflict*
   card, and lit even when it was not the human's turn or the phase forbids
   actions. Pressing it submitted `GameAction.playCard(conflictCard)` through
   `playSelected()`.
2. **Selector leak:** the target-selector listener re-enabled
   `playCardOnlyButton` (the wrong button) after a target was picked, and its
   enablement predicate read from a stale `selectedTarget` rather than the
   picker state, so the value it set was overwritten by any later state
   refresh.
3. **Shared dispatch:** both buttons called the same `playSelected()`, which
   branched on `instanceof ConflictCard` — the exact F4 conflation the task
   was meant to remove; button identity did not determine the action.

## Changes (one file: `b5ccg/src/b5ccg/ui/MainWindow.java`, +92/−52)

- New single enablement authority `updatePlayInitiateButtons()`:
  - `canInitiate = myTurn && conflictSelected && !activeConflict && phaseAllowsAction`
  - `canPlay = myTurn && selectedCard != null && !conflictSelected && phaseAllowsAction`
  - `targetReady = !conflictSelected || !targetSelector.isEnabled() || selectedTarget != null`
    — when the target selector is live for a conflict card, "Initiate
    Conflict" stays dark until an explicit target is chosen, so it can no
    longer fire on a stale auto-fallback target.
  - Reads only live state + current selection; never mutates selection, so it
    is safe from both state refreshes and programmatic selector changes.
  - An initiator can enable either button, so on ACTION/CONFLICT_RESOLUTION a
    conflict card with no active conflict lights "Initiate Conflict" (the
    draft's phase predicate was already this permissive — kept, per
    B5-0327's model; resolving the correct initiation window is a separate
    question, noted as deferred).
- Split dispatch: "Play Card" → `playOnly()` (guards `!(selectedCard instanceof
  ConflictCard)`), "Initiate Conflict" → `initiateOnly()` (guards
  `instanceof ConflictCard`, keeps B5-0325 human-target-first with auto-target
  fallback, requires a non-null target before submitting).
- New `clearSelection()` helper; the selection listener and the selector
  listener now route through the authority instead of setting button states
  directly (also fixes a latent stale-target leak: switching selection now
  resets `selectedTarget`).
- The old `playSelected()` is removed; refresh()'s inline three-branch block is
  replaced by one authority call. No button wiring, layout, or other task's
  features were changed (Sponsor/Promote/Build Influence, Support/Oppose,
  cost preview, initiative label, phase gating all untouched).

## Behavior matrix (after fix)

| Selection | State | Play Card | Initiate Conflict |
|---|---|---|---|
| conflict card | no active conflict, your turn, target chosen | off | on |
| conflict card | no active conflict, your turn, no target yet | off | off (target selector active) |
| conflict card | active conflict | off | off |
| non-conflict card | your turn, actionable phase | on | off |
| any card | not your turn / SETUP / END_ROUND / game over | off | off |
