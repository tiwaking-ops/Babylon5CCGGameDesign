reproduce or classify the transient DISCARD_AGENDA hand-membership FAIL,

## 2. Classification: stale verifier guard, NOT a wall-clock scheduling race

The failure is a **false negative in the harness verifier's hand-membership
guard**, triggered deck-draw-dependently. Evidence, file:line:

1. The offered action is legal and its payload is not a hand card by design:
   `AIPlayer.buildLegalActions` offers `GameAction.discardAgenda(p.getAgenda())`
   when `rules.canDiscardAgenda(p)` — b5ccg/src/b5ccg/ai/AIPlayer.java:344–346;
   factory GameAction.java:125–127. The payload is the IN-PLAY agenda.
2. Engine-side legality confirms hand membership is not the rule for this type:
   `canDiscardAgenda` requires only a non-Major agenda in play
   (RulesEngine.java:251–255); the controller branch validates
   `p.getAgenda() == action.getCard()` — agenda-in-play, not hand
   (GameController.java:308–311).
3. The step-[5/5] guard predates the B5-0364 agenda payload family:
   HeadlessSmokeTest.java:206–216 excludes only BUILD_INFLUENCE,
   PROMOTE_CHARACTER, USE_ROTATE_EFFECT from the `p.getHand().contains(card)`
   check. DISCARD_AGENDA / REPLACE_AGENDA / REVEAL_AGENDA are not excluded, so
   any live offer of them that wins AI scoring (DISCARD scores 1 MEDIUM /
   0.5 HARD vs PASS 0, AIPlayer.java:573–577 and 760–762) fails the check.
4. Not a race — the harness is single-threaded at the failure point: the daemon
   game loop thread has exited by the time step 5 runs (loop body ends when
   `state.isGameOver()`; harness polling loop breaks on
   `state.getRoundNumber() > 1`, HeadlessSmokeTest.java:113–131); there is no
   `System.exit` before step 5 (exit is the final statement, line 61) and
   ROUND_TIMEOUT_MS=120000 (a timeout would be a different failure class).
5. The per-run divergence is deck-shuffle randomness, not timing:
   Deck.java:11–15 and :42 use unseeded `Collections.shuffle`
   (java.util.Random default seed). StarterDeckBuilder.setRandomSeed
   (StarterDeckBuilder.java:64–69, 159–160) seeds only the random-pool deck
   picks, not the shuffle. Which player ends round 1 with a non-Major agenda
   in play AND scores DISCARD above every alternative is therefore a
   shuffle-draw conjunction — low probability per run, clock-independent.
   This also explains why failures name Alpha (checked first) and why
   B5-0476/B5-0492/B5-0494 saw "N of N standalone PASS then one in-window
   FAIL": the deciding variable is draw, not scheduling.

"Stale-offer" (the row's hypothesis A) is **refuted**: the offer is live and
legal on the final state. "Wall-clock scheduling race" (hypothesis B) is
**refuted** by (4). The true class is a **stale verifier guard** — the smoke
harness's step-5 exclusion list was never extended when B5-0364 added the
agenda lifecycle action family. The AI and engine behavior is correct.

## 3. Proposed slice (one)

**Guard-exclusion-list correction in HeadlessSmokeTest.java** (harness file
only, self-seedable per AGENTS.md §6): extend the step-[5/5] non-hand-payload
exclusion list to cover the agenda lifecycle family (DISCARD_AGENDA,
REPLACE_AGENDA, REVEAL_AGENDA), keeping the existing legality checks (null
action, null type, faction playability) untouched. Rationale: the engine
already enforces the real gates for these types (GameController.java:306–311),
and the suite covers their selection legality deterministically on constructed
states (HeadlessConformanceTest AGL section, :1049–1080).

Explicitly NOT the 0482-class seeded-RNG slice: seeding the shuffle would only
make this false negative deterministic (always-fail or always-pass per seed);
it cannot fix a verifier false positive. Seedable-shuffle infrastructure does
not exist today (Deck.java uses unseeded Collections.shuffle) and adding it
would be a model/ edit — out of proportion to the defect.

Latent-same-class note (observation only, no action proposed this pass): the
step-5 guard would misfire identically for any chosen action whose payload
references a non-hand-resident table card (e.g. BID_ON_MERCENARY's mercenary-
pool card) if such an action were ever the best live offer in the step-5
state; the agenda family is the observed trigger because it is offered in the
ACTION phase.

## Reusable lesson

A harness guard's exclusion list must cover every payload family its action
set emits — B5-0364 added agenda actions to the AI without extending the
smoke verifier's hand-membership exclusions, creating a draw-dependent ~7%
false-failure rate that mimics a concurrency flake; distinguish
verifier-defect from race by proving single-threadedness at the check point
and by finding the divergence source (unseeded shuffle here, not the clock).
