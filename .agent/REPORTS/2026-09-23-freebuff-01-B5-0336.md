# B5-0336 — Participation enforcement (proposal §8.3)

**Agent:** Buffy (deepseek-v4-flash) · **javac:** 1.8.0_292 · **Scope:** `b5ccg/src/b5ccg/model/`, `b5ccg/src/b5ccg/engine/` · **Claim:** live-held, released at close.

## What landed

Implements the `participation` schema semantics from
`docs/proposals/conflict-participation-restrictions-data-proposal.md` §3.2 as
engine-enforced behavior. Null/absent participation = open participation =
exact pre-B5-0336 behavior (§3.4); no data was touched (population is B5-0352).

* **NEW `model/Participation.java`** — immutable value object + self-contained
  Java-6 mini-parser for the participation fragment (strings, booleans, string
  arrays, flat object pairs). Unknown vocabulary keys/values are reported loudly
  on `System.err` and skipped, never coerced (§5.2); `allPlayersMustCommit` +
  `mustTakeSide` together produce a loud warning (§5.4 alternatives).
* **`model/ConflictCard`** — `participation` field + accessors (null = open).
* **`model/FleetCard`** — `fleetClass` field (§3.6). Null = class unknown; such
  a fleet cannot be proven eligible under a `fleetSubtypes` filter and is
  excluded from it, unaffected otherwise.
* **`model/Conflict`** — target-carrying constructor; `canJoinConflict(p)`
  ("players" gate); `canCommitCard(p, c)` (players gate + cardTypes +
  fleetSubtypes + perPlayerQuota + `leadersIncluded` character-alongside-allowed-
  committed-fleet rule); `commitCard`/`addParticipant` now return boolean and
  refuse illegal commits with loud detail at the refusal site; `commitMandatory`
  for engine-mandated commits (skips kind/quota filters — the mandate names the
  commitment — but still applies the players gate).
* **`engine/DeckLoader`** — `parseObject` values may now be nested objects/
  arrays (balanced-brace scan, string-escape aware, backward-compatible: flat
  objects parse identically); hydration of `participation` (malformed fragment
  → loud log, stays open) and `fleetClass`.
* **`engine/RulesEngine`** — `canInitiateConflict` 4-arg overload refuses
  `requiresTarget` conflicts initiated without a target (§3.2, rulebook Conflict
  round step 2); the pre-existing 3-arg form delegates with target null so every
  existing caller/test is unchanged. NEW `enforceMandatoryParticipation(conflict,
  state)`: before resolution, eligible players not yet participating are pulled
  in on the opposition side (mustTakeSide / allPlayersMustCommit /
  mustCommitAmbassador) and mandated face-up ambassadors commit via
  `commitMandatory`; non-CHARACTER `allPlayersMustCommit` and count > 1 are
  logged loudly as not auto-satisfiable (no card-picking semantics exist yet).
* **`engine/GameController`** — passes the action's declared target into the
  conflict (and logs it), rejects `requiresTarget` initiations with a distinct
  log line, calls `enforceMandatoryParticipation` before resolution, and the AI
  join path now respects the `addParticipant` participation gate.
* **`engine/HeadlessConformanceTest`** — new PAR section (22 checks): parser
  round-trip incl. unknown-key loud-skip, open-participation backward compat,
  players gate admit/refuse, cardTypes + fleetSubtypes incl. fleetClass-less
  exclusion, perPlayerQuota, leadersIncluded both ways, requiresTarget through
  both initiation forms, all three mandatory-commit dimensions, and live
  DeckLoader hydration of participation + fleetClass.

## Limits (recorded, not silently dropped)

* `allPlayersMustCommit` auto-satisfies only the ambassador (CHARACTER);
  other kinds and count > 1 log loudly and remain unresolved until the engine
  grows per-kind card-picking semantics.
* `players: TARGET`-only conflicts rely on the declared target; a conflict
  initiated without a target keeps target null and admits nobody extra —
  only possible when `requiresTarget` is false.
* §4 data values (six cards) are B5-0352's job; until then every real card
  participates openly.
