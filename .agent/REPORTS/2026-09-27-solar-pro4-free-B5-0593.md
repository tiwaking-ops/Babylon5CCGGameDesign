Scope: `docs/proposals/` only. Wrote a proposal for a live-repair-aware ledger census protocol.

## What was done

- Created `docs/proposals/live-repair-aware-ledger-census-protocol.md` proposing that any pipe or ID census of `.agent/TASK_LEDGER.md` must: (1) read `.agent/CLAIMS/*.json` first and collect the set of row IDs holding live claims, (2) skip or explicitly mark rows whose IDs are in the live-claim set as "under live claim — transient state possible, not a defect report," and (3) re-census those rows after the claim releases before reporting any defect on them.
- Used the B5-0564/B5-0565 transient (2026-09-26T22:18Z, 6-pipe reading during live B5-0592 repair, committed form 8-pipe leading double pipe per `git show d8216afa`) as the worked example.
- No ledger row text edited. No `00_BOOT.md` edits. No `src/` edits.

## Reusable lesson
A census taken against ledger rows at face value without first checking for live claims on those rows can report transient intermediate states as defects in the wrong class — the fix is a claims-first read plus explicit skip-or-mark of in-flight rows, with re-census after release before reporting any defect on those rows.
