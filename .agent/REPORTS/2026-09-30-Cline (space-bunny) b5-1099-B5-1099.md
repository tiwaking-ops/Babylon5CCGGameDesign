## The trap: the compile gate is green and is not this row's gate

```
b5ccg/compile.bat  ->  Build successful (1 warning: bootstrap class path not set
                        in conjunction with -source 1.6)
```

That is `compile.bat`, which by **decision** (recorded in its own trailing
comment) carries **no test branch** - the test selection lives only in
`compile.sh`'s `RUN_TESTS=1` branch. So `compile.bat` exiting 0 is *not* the
row's "compile green plus suite green" gate. The real gate:

```
java -cp b5ccg/out b5ccg.engine.HeadlessConformanceTest
-> CONFORMANCE SUITE FAILED - unexpected exception:
   java.lang.ClassCastException: b5ccg.model.FleetCard cannot be cast to
   b5ccg.model.ConflictCard
     at b5ccg.engine.HeadlessConformanceTest.testParticipation(HeadlessConformanceTest.java:507)
     at b5ccg.engine.HeadlessConformanceTest.main(HeadlessConformanceTest.java:6245)
```

This is the B5-0336 participation defect that B5-1087 triaged and B5-1088 was
written to fix. It is `engine/` plus suite-file scope, one writer at a time, and
is **not fixed here** per `.agent/00_BOOT.md` step 8.

## Why working it anyway would have been wrong even if permitted

The task's deliverable is a *regression* assertion: "the generic 1-1-1 shape is
unchanged for all other records". A red suite at `testParticipation` cannot
certify that, and the section this row would append lives in the very file that is
throwing. The evidence would have been unrunnable at best, and at worst a green
section printed above a red suite read as a pass.

## Reusable lesson

Measure the gate the row actually names, not the nearest gate that happens to
look green: `compile.bat` is compile-only by decision, so a task whose gate says
"suite green" can read green on compile and still be blocked. Corollary - when a
row's gate names both a predecessor row and a tree state, check the predecessor's
*own* gate too, because a chain of `OPEN` rows is a red gate wearing an `OPEN`
status.
