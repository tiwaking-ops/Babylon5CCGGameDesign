# B5-0372 — D6 unlimited-action-loop implementation

**Agent:** solar-pro4:free | **Date:** 2026-09-24 | **JDK:** 1.8.0_292

## Summary

Implements D6 (rulebook §III "The Action Round" — initiative cycles until all
players pass consecutively) per the B5-0341 design proposal. Lands the engine
+ AI slices that the prior BLOCKED entry (GPT-6 Codex, 2026-09-24) identified
as necessary but out of reach under an engine-only scope.

## Changes

### GameController.java (`b5ccg/src/b5ccg/engine/`)

**`runActionPhase()`** — the loop's consecutive-pass skeleton (`passCount`
resets to 0 on any non-pass action, round ends at `passCount == playerCount`)
is preserved verbatim; three additions:

1. **Un-passing.** `current.setPassed(false)` on every non-PASS action.
   Rulebook §V: "A player who passes may act later in the action round."
   Previously the `passed` flag was sticky within the round.
2. **Safety cap (non-rulebook, liveness only).**
   `MAX_ACTIONS_PER_ROUND = playerCount * 8`, checked at the top of each
   cycle iteration. Logged loudly if hit; ends the round. With the resource
   bounds in §3.4 of the proposal this should never fire in a well-behaved
   game — it is belt-and-braces against a pathological AI scoring bug.
3. **`totalActions` counter** drives the cap.

**`processAction()`** — removed the trailing `p.useAction()` call. Under D6
the loop itself delivers exactly one action per eligibility visit; the
per-player `actionsLeft` field is no longer the ACTION-round gate.
`Player.resetActions()` still sets `actionsLeft = 1` at round start (called
by `RulesEngine.startRound`), and `actionsLeft` is preserved for backward
compatibility, but nothing in the ACTION path reads it as a cap anymore.

### AIPlayer.java (`b5ccg/src/b5ccg/ai/`)

**`buildLegalActions()`** — removed the B5-0202c early return:

```java
// REMOVED:
// if (p.isPassed() || p.getActionsLeft() <= 0) return actions;
```

The AI may now be offered actions in every cycle. Termination is preserved by:
- PASS is always offered (unchanged);
- MEDIUM/HARD scoring floors at 0 — when all scores are ≤ 0, PASS wins;
- EASY retains the 30% pass bias (`rng.nextInt(10) < 3`);
- Every non-pass action consumes a renewable-only-at-round-start resource
  (influence from the applied pool, a ready card, a rotation, the
  one-conflict-per-turn marker).

**`Player.java`** — untouched. `resetActions()` still clears `passed` at
round start; `actionsLeft` remains at 1 but is not consulted as an ACTION-round
gate.

### Conformance assertions (HeadlessConformanceTest.java)

Four assertions that checked `actionsLeft == 0` after a direct
`processAction` reflection call were updated to `actionsLeft == 1` with
explanatory comments, because `processAction` no longer calls `useAction()`
and a handler invoked in isolation does not spend an action under D6:

| Section | Old check | New check |
|---------|-----------|-----------|
| LEAD    | "exactly one action consumed per pair" → `actionsLeft == 0` | "leader rot + fleet led (D6: no per-handler action spend)" → `actionsLeft == 1` |
| ROT-C   | "handler rotates and flags through the generic branch" → `actionsLeft == 0` | same description, `actionsLeft == 1` |
| ATK     | "controller rotates and commits attacker, spends one action" → `actionsLeft == 0` | same description, `actionsLeft == 1` |
| HLR     | "controller repairs two tokens, rotates fleet, spends two pool and one action" → `actionsLeft == 0` | same description, `actionsLeft == 1` |

The `appliedPool == 0` sub-check in the HLR assertion is preserved (it
validates the repair-spend behavior, which is unchanged).

## Behavior deltas

- All-AI rounds now contain more than 8 actions when AI players have
  affordable actions (sponsor / promote / build / lead-fleet / rotate-effect
  can all fire multiple times per round). The smoke test's "32 AI actions"
  reflects this — it is higher than the pre-D6 baseline because the same 4
  AI players now take multiple actions per round until resources are
  exhausted or they pass.
- EASY pass bias (30%) keeps easy games short; the consecutive-pass end
  condition still fires correctly (a single non-pass from any player resets
  the counter).
- Human play is unaffected: the UI keys on turn/phase, not action count, so
  B5-0327 phase gating and action-button enablement continue to work.

## Risks

- **R1 (game length):** more actions per round lengthen games. Mitigation:
  EASY pass bias; the 600 ms per-action pause is per action, not per player.
  B5-0349's multi-round runner can quantify before/after if needed.
- **R2 (AI inflation):** D9's applied pool (B5-0369, already landed) bounds
  per-round spends — influence spent comes from the per-turn pool, which
  restores only at round start. Without D9 this would be a real problem;
  with D9 landed the pool is the correct limiter.
- **R3 (liveness):** the scoring floor + EASY pass bias + the safety cap
  together guarantee termination. The cap log assertion is acceptance
  criterion 5 from the proposal; it did not fire in this session's runs.
