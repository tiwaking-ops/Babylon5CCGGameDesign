## Root-cause analysis

Two distinct bugs caused the 4 stable MINES failures on the committed tree (b5eabc89):

### Bug 1 — Log format: closing paren before terminal period

`RulesEngine.executeAttackConflictParticipant` emitted:

```java
+ returnDamage + " damage returned)." )
```

producing `(N damage; M damage returned).` — closing paren **before** the
period. The conformance assertions used `logContains(st, "...damage returned.")`
expecting the period **after** `returned` (inside the parens). The `.contains()`
substring check therefore never matched, failing:

- `reactive mines adds +1 return damage (fleet)` (expects `"2 damage; 4 damage returned."`)
- `legacy fleet +1 enhancement does not add return damage` (expects `"1 damage; 3 damage returned."`)
- `round-trip: mines played then attack triggers +1 return damage` (expects `"2 damage; 4 damage returned."`)

**Fix**: `RulesEngine.java`, line ~860 — move the closing paren after the
period: `" damage returned.)"`. This is a one-character reorder (paren vs period).

### Bug 2 — Round-trip mines card id not in the reactive registry

The round-trip Scenario 3 used an `EnhancementCard` with id `"enh_mines_rt"`.
`CardEffects.damageOnAttack()` gates on a hardcoded `DAMAGE_ON_ATTACK` set that
contained only `"enh_mines"`, `"de_enh_mines"`, `"enh_energy_mines"`, and
`"de_enh_energy_mines"`. The test fixture's `"enh_mines_rt"` was unregistered,
so the reactive `+1` never fired for the round-trip attack, producing
`3 damage returned` instead of the expected `4 damage returned`.

**Fix**: `CardEffects.java` — registered `"enh_mines_rt"` in the
`DAMAGE_ON_ATTACK` static initializer.

### Why only 4 failures (not 6)

Two assertions that FAILED in the B5-0544 sweep now PASSED in the working tree:

- `attacker may attack the fleet target` — PASS (the uncommitted fixture changes
  moved the attacking character from `getInnerCircle()` to `getSupportingRole()`
  at leadership 2, satisfying `canAttackConflictParticipant`'s nonzero-primary-stat
  gate).
- `defender fleet survives reactive mines (no severe)` — PASS (same fixture:
  attacker leadership 2 → `attackDamage = 2` → `defFleet.getDamageTokens() == 2`).

These fixture corrections (leadership 0→2, InnerCircle→SupportingRole, removing
pre-applied `applyDamage` calls, adjusting expected log strings) were already in
the working tree from a prior session (Buffy, unknown).

## Reusable lesson

When a test asserts via `String.contains()` on a formatted log line, the
format string's punctuation must exactly match the assertion's expected
substring — a single misplaced paren or period causes a silent substring
miss with no visible error in the log output itself.
