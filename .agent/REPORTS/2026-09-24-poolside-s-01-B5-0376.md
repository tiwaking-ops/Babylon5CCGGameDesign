## Summary

Completed the B5-0376 war-conflict initiation and participation conformance tests.
The Phase A engine/model code (`WarKind`, `TensionMatrix`, `GameState.isAtWar`,
`RulesEngine.declareWarConflict`/`canDeclareWarConflict`,
`GameController.DECLARE_WAR_CONFLICT` branch, `LocationCard.capturedBy` stub)
was already in place. The single blocker was a test-harness bug in
`HeadlessConformanceTest.state()`.

## Root cause

`state(Player... players)` constructed the `GameState` with an empty list and
then appended players to the *local* list afterward:

```java
List<Player> ps = new ArrayList<Player>();
GameState s = new GameState(ps);          // copies empty list
for (Player p : players) { ps.add(p); p.setGameState(s); }
```

`GameState(List<Player>)` performs `this.players = new ArrayList<>(players)` —
a defensive copy. The subsequent `ps.add(p)` calls mutated the local list, not
the copy inside GameState. Result: `GameState.getPlayers()` was always empty,
so `GameState.isAtWar(Faction)` (which iterates `players`) always returned
`false`, even though `TensionMatrix.isAtWar(a, b)` returned `true`.

## Fix

Reordered `state()` to populate the player list **before** constructing GameState:

```java
List<Player> ps = new ArrayList<Player>();
for (Player p : players) { ps.add(p); }
GameState s = new GameState(ps);
for (Player p : players) { p.setGameState(s); }
```

No production source files were modified — only the test harness helper.
