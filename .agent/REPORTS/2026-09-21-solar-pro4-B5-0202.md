## Rulebook sections consulted

- §III "The Conflict Round" (line 362): each faction may declare one conflict per turn
- §III "The Action Round" (line 376-378): players act one at a time; a player may pass; consecutive passes end the round
- §IV "Conflict Cards" (line 544): "Each faction may normally initiate only one conflict per turn"
- §V "ACTION: Rotate to Build Influence" (line 667-669): any faction with Influence Rating ≤ 9 may rotate an IC character + apply 3 influence to gain +1 Influence Rating

## Audit findings (7 total)

### Finding 1 — AI offers duplicate conflict initiation within one turn (RULE INVALID) — FIXED
**Severity:** medium-high  
**Rulebook ref:** §III line 366, §IV line 544 — one conflict per faction per turn.  
**Files:** `AIPlayer.java` lines 61-66 (`buildLegalActions`).

`buildLegalActions()` adds `INITIATE_CONFLICT` for every `ConflictCard` in hand against every other player, unconditionally. In a 4-player game with 4 conflict cards in hand this produces up to 12 `INITIATE_CONFLICT` entries for a single `chooseAction()` call.

The engine's `RulesEngine.canInitiateConflict()` does not currently guard against re-initiation (it checks `isPassed()`, `actionsLeft`, hand membership, and faction playability — but not "a conflict is already active this turn").

**Fix applied:** Added a guard `if (state.getActiveConflict() == null)` around the `ConflictCard` branch in `buildLegalActions()`. Now the AI only offers conflict initiation when no conflict is currently active. This is the smallest fix that removes the rule-invalid option from the AI's action space without touching model/ or engine/.

### Finding 2 — `buildLegalActions` does not check `isPassed()` / `actionsLeft` (low, no fix)
**Rulebook ref:** §III "The Action Round" (line 378).  
`buildLegalActions()` doesn't check whether the player has passed or is out of actions. In practice the engine only calls `chooseAction()` for the active player who hasn't passed, so this never manifests. Not rule-invalid in practice; noted for completeness.

**Fix:** Deferred — would add `RulesEngine` dependency to `AIPlayer` (crosses scope). The engine rejects invalid actions at `processAction` time anyway.

### Finding 3 — EASY AI has a 30% pass bias even when legal actions exist (low, quality only, no fix)
**Rulebook ref:** §V "ACTION: Pass" (line 738) — pass is always legal.  
`easyChoose()` returns `GameAction.pass()` 30% of the time (`rng.nextInt(10) < 3`) even when legal non-pass actions exist. This is documented as intentional EASY-tier behavior in the class javadoc. Not rule-invalid; a design choice.

**Fix:** Deferred — changing EASY strategy is a design decision, not a rule-correction.

### Finding 4 — AI has no Build Influence action (MEDIUM, deferred — requires model + engine changes)
**Rulebook ref:** §V "ACTION: Rotate to Build Influence" (line 667-669).  
The AI never builds influence, which is a core rulebook action available to any faction at ≤ 9 influence (all 4 factions start at 4). Fixing requires: (a) `BUILD_INFLUENCE` in `GameAction.Type`, (b) `GameAction.buildInfluence()` factory, (c) `canBuildInfluence()` in `RulesEngine`, (d) `processAction()` branch, (e) `AIPlayer.buildLegalActions()` addition + scoring. Crosses into `model/` and `engine/` scope.

**Fix:** Deferred to B5-0203 or a dedicated follow-up. This is the highest-priority deferred item.

### Finding 5 — Engine allows re-initiation of conflicts (engine-side gap — ai/ cannot fix)
**Rulebook ref:** §IV line 544 — one conflict per faction per turn.  
`RulesEngine.canInitiateConflict()` doesn't check whether a conflict is already active, and `GameController.processAction(INITIATE_CONFLICT)` resolves synchronously and clears `state.activeConflict`, so a faction can initiate a second conflict on its next action. The full fix requires tracking "conflicts initiated this turn" per player in `GameState` and checking it in `canInitiateConflict()`.

**Fix:** Out of B5-0202 scope (`ai/` only). The Finding 1 guard in `buildLegalActions()` mitigates this at the AI level but doesn't fully close it. Reported for B5-0203 or engine follow-up.

### Finding 6 — AI scoring doesn't account for influence cost of card play (low, quality only, no fix)
**Rulebook ref:** §V "ACTION: Sponsor a Supporting Card" (line 651-653).  
The AI scores card plays based on card type (Agenda=8/9, Location=6/7, etc.) but doesn't subtract the influence cost. A card costing 3 influence and giving a one-time +1 event scores the same as a free card with the same effect.

**Fix:** Deferred — requires the engine to expose per-card influence costs (currently not modeled; `Card` has no `influenceCost` field). Cross-scope.

### Finding 7 — AI never promotes characters to Inner Circle (low-medium, deferred — requires model + engine changes)
**Rulebook ref:** §V "Sponsor a Supporting Card" (line 651) vs "Promote a Character to the Inner Circle" (line 663) — two distinct actions.  
`buildLegalActions()` generates `RECRUIT_CHARACTER` for every `CharacterCard` in hand, but `GameController.processAction(RECRUIT_CHARACTER)` places the character directly into the supporting role. Promotion to IC is not a `GameAction` type and is not offered by the AI.

**Fix:** Deferred — requires `PROMOTE_CHARACTER` `GameAction.Type`, `canPromoteCharacter()` check, and wiring into both `GameController` and `AIPlayer`. Cross-scope (model + engine + ai).

## Fix applied

One hunk in `AIPlayer.java` `buildLegalActions()`:

```java
if (c instanceof ConflictCard) {
    // Rulebook §IV: one conflict per faction per turn.
    // Do not offer a second initiation while one is active.
    if (state.getActiveConflict() == null) {
        for (Player target : state.getPlayers()) {
            if (target != p) {
                actions.add(GameAction.initiateConflict(c, target));
            }
        }
    }
}
```
