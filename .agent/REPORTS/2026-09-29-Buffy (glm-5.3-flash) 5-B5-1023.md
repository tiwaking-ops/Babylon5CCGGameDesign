# B5-1023 - Adjudication of the orphan `timing` field on `de_event_armistice`

Report-only: no card JSON edited, no field propagated, no src edited, no commit.
Instruments named: direct reads of both card files, `grep -rn` over `b5ccg/src`
and the frozen archive, the rulebook text, and the twin census of record
(DECISIONS B5-1020-wave entry).

## The two records, verbatim

Premiere twin (`event_armistice`, [premiere.json:4044](b5ccg/resources/cards/premiere.json#L4044)):
```
"id": "event_armistice", "title": "Armistice", "type": "EVENT", ... "set": "PREMIERE",
"text": "Play before a conflict resolves. Cancel one Military conflict. No Aftermath cards may be played."
```
— no `timing` key.

Deluxe twin (`de_event_armistice`, [deluxe.json:3248](b5ccg/resources/cards/deluxe.json#L3248)):
same fields, same core text plus the annotated deluxe errata ("...the player who
played Armistice gains 1 Influence."), **plus one trailing key: `"timing": "ANY"`**
— the only occurrence of the key in either file (1 of 829 records; also the only
field-set asymmetry among all 325 twin pairs).

## Question 1 - is the premiere twin supposed to carry it?

No. The premiere twin encodes its timing purely in prose, exactly like every other
event in both files ("Play any time", "Play before a conflict resolves"). The
deluxe twin carries the *same* prose unchanged — so the structured key is
redundant with its own text surface, not a replacement for it. If the deluxe
editor had meant to make timing structured, the other 95 deluxe events (all with
"Play any time" prose) would have been converted too; none were.

## Question 2 - what would `ANY` mean against the rulebook?

Nothing defined. The rulebook's only "timing" content is §II *"Playing 'Fast and
Loose' and Resolving Timing Disputes"* — a table-procedure rule, not a card
attribute. Worse, **the value contradicts the card's own prose if read as a
structured timing dimension**: `ANY` corresponds to the "Play any time" family,
while Armistice's text restricts play to "before a conflict resolves". A structured
field that says *anytime* on a card whose text says *windowed* is internally
inconsistent — the strongest single piece of evidence that it is not a deliberate
encoding.

## Question 3 - does any code consume it?

None, at any point in the repo's history:
- `DeckLoader.buildCard` reads a fixed key set; unknown keys are silently ignored,
  so today the field is inert cargo on the parsed `Card`.
- `grep -rn timing b5ccg/src` hits only prose comments (AIPlayer event-timing
  remarks, HeadlessConformanceTest aftermath-timing section) — no `get("timing")`,
  no field, no loader.
- `grep -rn timing b5ccg/src-java8-archive/` (frozen pre-Java-6 original): zero
  hits — the field was **never** consumed even by the code the data was
  presumably written against.

## Verdict: DATA-ERROR (stray hand-edit), recommend removal via an authorised row

| Hypothesis | Verdict | Evidence |
|---|---|---|
| Unimplemented feature this card was written for | **Rejected** | No loader ever read the key (archive included); no vocabulary exists (a real feature would need at least a second value to contrast with `ANY`); the value contradicts the card's own prose. |
| Schema the other 828 records are missing | **Rejected** | The dataset's timing convention is prose, uniform across ~96 events in both files; 828 records do not "miss" a field that has no defined meaning. Propagating an undefined value is how a typo becomes a standard (the row's own warning). |
| Stray hand-edit / transcription accident | **Accepted** | Single-occupant sparse field (the pool-baseline report's own heuristic: "sparse fields with a single occupant are usually a hand-edit rather than a schema decision"); trailing position; contradicts host prose; zero historical consumers. |

**Disposition:** removal of the one key from `de_event_armistice` is the right
action — but by this row's own terms it must happen through a separate authorised
data-edit row, never silently, and never by propagation. **No follow-up row is
seeded for a loader**: the structured key duplicates what the prose already encodes,
and the prose is the contract every other event follows. The actually-open gap on
this card (the cancel-one-Military-conflict effect is not dispatched at all —
`CardEffects` has no armistice entry) is already in the B5-0741 follow-on family
and needs no new row.

Related advisory surface, noted not acted on: the 2026-09-28 card-image diff
report describes a *different* deluxe Armistice text ("Rotate your ambassador..."),
which is the rendered-art-vs-pool-data question, already under separate
investigation rows.

## Reusable lesson

A single-occupant field is adjudicated by triangulating three independent
evidence classes — consumers (none, ever), vocabulary (undefined), and internal
consistency (contradicts its own card's prose) — and three rejections of the
"meaningful" hypotheses converge on stray-hand-edit faster than any single
signal could.

doubleLead no by `ledger-query.ps1 -Status "*"`.
