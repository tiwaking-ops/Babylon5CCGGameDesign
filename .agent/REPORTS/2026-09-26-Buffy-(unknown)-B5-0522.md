## Same-class defect fixed in the 0487 fleet handler (disclosed)

The B5-0487 fleet button handler tested `enh.hasExplicitTarget()` to choose
between the targeted path and the self-target fallback — but the seam is set
*inside* `playCensureWithTarget` immediately before submit, so a fresh hand
card never tests true and every targeted click fell through to the legacy
self-target path (self-penalizing), exactly the human-unreachable class
B5-0522 was seeded to close. Both handlers now route on the picker's
selection (null selection ⇒ self-target fallback, which is unreachable while
the button's enablement gate requires a selection). Applied to the fleet
handler under the B5-0435/B5-0490 same-class-defect precedent (0490's scope
named 0486 only; the corruption class was identical); disclosed here per that
precedent.
