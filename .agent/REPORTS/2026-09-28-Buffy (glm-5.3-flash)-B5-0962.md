**Two integrity defects, not one:**

1. **The enum violation the validator catches:** `state: "released"` is not in

2. **A future-dated `utc` the validator does NOT catch:** `22:40:00Z` against a wall
   clock of 19:02Z at measurement (**+3h38m**) and against the file's own mtime of
   09:36:25Z (**+13h04m**) — the local-time-written-as-UTC shape (the +13:00 offset
   is exactly this machine's zone), the same class B5-0653 fixed for claims and
   B5-0949 flagged in another heartbeat payload. **Liveness is unaffected**: the
   three-signal heartbeat signal is mtime-based (measured corroboration this session:
   `ledger-query` printed a 56.5-minute heartbeat age for a file whose payload `utc`
   was future-dated — the age matches mtime, not payload). But the validator passing
   a future-dated `utc` in silence is a tooling gap worth a future row; not fixed
   here, this row touches no tool.

## The decision: quarantine-pointer report (option a), and why

- **The owner cannot deliver the correction.** Per the human ruling recorded in
  `.agent/HEARTBEATS/README.md` R1, an `agent_id` names a *session instance* —
  `Cline (space-bunny) b5-0941` was a per-task session that has ended (its close-out
  is complete: row DONE, report and pattern filed, claim deleted). There is no living
  owner to edit it, so option (b) is not merely discouraged, it is unavailable.
- **Editing it would be fabrication** (AGENTS.md §6: never edit another agent's
  heartbeat — not even a colliding one), and deleting or moving it is forbidden by
  this row. The `_quarantine/` directory exists, but this row authorises a *pointer*,
  not a store mutation.
- **The payload is a tombstone whose information is already recorded elsewhere:**
  the B5-0941 row reads DONE with a full note; the close-out report and pattern exist;
  `live_claims: []` asserts nothing is held. The `released` value is semantically
  redundant with the `[]` + `null` pair (B5-0951's branch-2 finding, re-confirmed
  here with fresh numbers), and `state` has no behavioural consumer in the toolchain —
  B5-0951 measured that only `validate-heartbeats.ps1` and the unused
  `migrate-heartbeats.ps1` read it, while liveness comes from the three-signal rule.
- **The one-line fix (`released` → `idle`) remains available to the owner-of-record's
  principal or a human**, exactly as B5-0951 recorded; this report is the pointer
  that makes it findable. Until then the validator's exit 1 is *correct output* and
  stands — deliberately not bought by widening the enum (no lifecycle meaning was
  ever recorded for `released`, and B5-0951's three reasons against widening all
  re-verify).
