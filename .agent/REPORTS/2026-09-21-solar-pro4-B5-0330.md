# B5-0330: Zone overflow guard (F11)

## Summary

Added "(+ N more)" overflow indicators to the three card zones in
`GameBoardPanel.drawZone()` so players can see when their Inner Circle,
Fleets, or Groups/Locations exceed the render space.

## Problem (B5-0310 audit, F11)

When a player's Inner Circle, Fleets, or Groups/Locations rows exceed the
width of the player zone, the extra cards are silently clipped. There is no
visual indicator that cards are off-screen. B5-0310 §Rendering audit:
"Implementation plan: add an 'N more' overflow indicator below each section
when cards overflow the render area."

## Implementation

**File:** `b5ccg/src/b5ccg/ui/GameBoardPanel.java`

Three sections modified in `drawZone(Graphics2D g, Player p, int x, int y, int w, int h)`:

### Inner Circle

Count cards drawn (`icDrawn`). After the loop, if `icDrawn < p.getInnerCircle().size()`,
render `(+ N more)` in yellow below the row.

### Fleets

Count cards drawn (`flDrawn`). After the loop, if `flDrawn < p.getFleets().size()`,
render `(+ N more)` in yellow below the row.

### Groups/Locations

Count cards drawn across both collections (`glDrawn`, with `glTotal = groups + locations`).
After both loops, if `glDrawn < glTotal`, render `(+ N more)` in yellow below the row.

All overflow indicators use:
- Color: `new Color(200, 180, 100)` (warm yellow, distinct from zone label colors)
- Font: `SansSerif, PLAIN, 8` (small, unobtrusive)
- Position: `x + 8, cy + 58` (directly below the last rendered card row)

The break condition `if (cx + 50 > x + w - 4) break;` is unchanged — it
determines when cards would overflow. The new counters track how many were
actually drawn before the break, and the delta is displayed.

## Edge cases

- Empty zone (size 0): no indicator, since 0 drawn == 0 total.
- Zone fits all cards: no indicator, since drawn == total.
- Mixed Groups + Locations: both collections share the same counter/row,
  so the indicator covers the combined overflow.
