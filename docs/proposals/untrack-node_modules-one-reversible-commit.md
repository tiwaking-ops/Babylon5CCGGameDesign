# Proposal: untrack the 67,258 tracked `node_modules` files in one reversible commit

`git rm --cached`) has been run, `.gitignore` is untouched, no commit, no push, no `b5ccg`
edits. Execution is a **human decision**; this file exists so that the action, when ratified,
is one explicitly-approved claimable step with a written-down, reversible scope.

## The one action being proposed

Exactly **one** commit that (a) appends `node_modules/` to `.gitignore`, (b) untracks the
directory from the index only, and (c) leaves every file on disk byte-identical.

```bash
# 0. Preconditions (each must hold before proceeding):
#    - no live claim over .gitignore or the commit itself (check .agent/CLAIMS/)
#    - working tree clean of UNRELATED in-flight bytes, or their owners have
#      agreed in writing that this commit may exclude them; this proposal
#      deliberately does NOT sweep the whole tree - stage exactly three things:
git add .gitignore
git ls-files -z node_modules | xargs -0 git rm --cached -q --
git add -u node_modules 2>/dev/null || true   # no-op safety: nothing left to stage
# 1. Verify before committing:
git ls-files | grep -c node_modules   # expected: 0
git status --porcelain | grep -c "^D" # expected: 67258 (index-only deletions)
#    - spot-check that files still exist on disk: ls node_modules/<any pkg> must list
# 2. The commit (message text for the human to ratify or edit):
git commit -m "Untrack node_modules (67,258 files) - checkpoint residue from 418664de; ignore going forward

Files remain on disk; only the index changes. Reversible with: git reset --hard HEAD~1 (or git revert).
History rewrite (Phase 2) is OUT OF SCOPE and requires separate explicit human approval."
# 3. NOT in this action: git push. NOT in this action: history rewrite, pack purge,
#    `git filter-repo`, or any Phase 2 work.
```

| Reversal | `git reset --hard HEAD~1` (or `git revert`) restores tracking exactly; **`git rm --cached` is reversible, a history rewrite is not** |

## Explicitly out of scope

* History rewrite / pack purge / object-store shrink (Phase 2) — needs separate explicit
  human approval, and is the reason reversal language matters here.
* Untracking the other tracked-root litter (`.qwen/`, `.freebuff/`, `ledger.bak`, `Pene/`,
  harness dirs) — **B5-0923 owns that question**; its no-untracking boundary stands.
* Any `b5ccg` source, card data, or `.agent` governance content.

## Why this can't be repaired if botched by sweeping (the constraint that shaped the proposal)

`00_BOOT` step 8 and the B5-0737 BLOCKED record both establish: a tree-wide commit must not
capture another agent's live in-flight bytes. The proposed sequence stages **exactly**
`.gitignore` + index removals, so it composes safely with a dirty tree — but the preconditions
above still require the human to time it when no live claim conflicts with the three staged
paths.

## Reusable lesson

A proposal that would execute a one-way-looking operation earns trust by writing the
**reversal** next to the action: the same paragraph that says what the commit does must say
which single command undoes it, before anyone is asked to approve it.
